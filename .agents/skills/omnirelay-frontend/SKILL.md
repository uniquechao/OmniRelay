# OmniRelay 前端

以用户最新确认的可运行原型为验收基准。仓库内入口为 [原型与设计索引](../../../design/README.md)，规则与入口对应关系见 [UI 规范](../../../design/specs/omni-relay-ui-standards.md)。用户提供新版原型时，先定位对应页面和状态，核对仓库副本是否同步，记录采用的基准。正式工作台代码位于 `web/`。

## 实现与评审

1. 先运行原型，再读对应 HTML、CSS、JS。记录入口、页面状态、操作路径和引用的颜色变量。颜色从原型的 [主题变量](../../../design/prototype/omni-relay-colors.css) 和 [交互样式](../../../design/prototype/omni-relay-interactions.css) 获取。
2. 以 1:1 为验收条件。复现布局、尺寸、字体、间距、语义色、主题和动效。沿用原型的入口、文案、操作顺序、键盘与触屏、焦点、关闭方式、校验、确认、反馈和权限可见性。区分已批准的状态与尚无设计的状态。正式数据与认证走实际接口，原型数据和账号仅用于演示。
3. 用同目录的 [Impeccable](../impeccable/SKILL.md) 检查成品在浏览器中的视觉层次、可读性、响应式和动效。用 [Vercel Web Design Guidelines](../web-design-guidelines/SKILL.md) 检查语义、焦点、表单校验、触控、主题以及减少动态效果。两者的发现应落实为具体状态、文件位置和可复现问题。任何改变已确认视觉、交互或功能的建议需先获得用户认可。纯评审任务只提交发现。
4. 对照运行。原型与实现使用相同视口、字体设置、主题、用户权限、数据和 UI 状态。至少检查受影响的桌面与窄屏、浅色与深色，并操作关键路径。动效分别核对静态帧和实际播放。记录已比对的状态和具体差异。缺少可运行实现或证据时，明确尚未通过 1:1 验收。

## 两条参考路径

- **登录 `#/login`**：比对品牌区、语义色、栅格、四圈波纹和减少动态效果。实测账号密码登录、飞书授权、取消、错误提示及重新进入原页面。
- **用户管理 `#/system/users` → 查看**：比对 480px 抽屉及窄屏宽度、层级、状态色、组织级和项目级授权。实测就地添加、项目选择、重复校验、保存、撤销确认、未保存提示及关闭后焦点还原。
