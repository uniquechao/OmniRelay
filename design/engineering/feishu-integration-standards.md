# 飞书接入工程师实现标准与约束

适用设计：[飞书 Bot 配置、登录与通讯录同步](../specs/omni-relay-feishu-integration.md)。本文件随 `.panda/plans/feishu-integration-v1.md` 的每项任务引用，作为执行与评审约束。

## 通用标准

- 开工先读根目录 AGENTS.md、CLAUDE.md、接入设计及本任务。若 `.panda/modules/INDEX.md` 已生成，再读对应 MODULE.md 和当前 issue 过程页；当前未初始化，不擅自创建模块或写入可触发执行的 issues 目录。
- 接入设计 §1–6 是本批需求依据；较早架构中自动建档等描述以本次明确的“管理员开通已有账号”约定为准。冲突或真实平台能力不符时记录证据及影响，调整契约后同步消费者，不能静默换协议。
- 每个 issue 同时交付实现、针对行为的测试和必要文档。先复现缺口，再改代码，再跑对应验证；已有行为应复用并回归，不把已有功能重写一遍。仅为本批需求引入依赖，锁定实际版本及许可证。
- 单部署单组织单应用；Bot、OAuth、目录独立运行。身份只由可信 `(tenant_key, app_id, open_id)` 对应已启用本地账号，姓名和邮箱不能作为账号合并依据。目录同步不能创建账号、授予角色或代替管理员停用账号。
- App ID、Tenant Key、App Secret、公开地址及非敏感凭据代次来自部署。管理页只能保存 Bot 开关；组织和应用迁移不属于本批任务。缺凭据须明确表达，不能伪装成认证成功，也不能退回演示数据。
- 秘钥、令牌、OAuth code、PKCE verifier、Cookie 不进入响应、日志、审计、APM、截图和浏览器存储；入口访问日志不采集 OAuth callback 查询串。诊断只保留请求 ID、飞书请求 ID、脱敏错误码和必要时间。
- 每次服务端鉴权；会话失效 401，权限或 CSRF 不足 403。管理写请求验证同源 Origin 与 X-CSRF-Token。Bot 检测虽不改变开关，POST 仍需 CSRF。页面能力仅控制展示。
- 时间为 UTC RFC 3339；字段、枚举、状态码、版本语义严格遵循接入设计。新增/变更先更新契约样例及正反例；禁止前后端各自推测字段。
- 不夹带任务查询、派单、DSH、自动回复、简报或全套 K8s 建设。Bot 本批交付终点是可信事件与待路由工作持久化。

## 后端工程师

### 所有权与边界

- `internal/system` 持有 Bot 管理领域、HTTP 和检测任务；`internal/feishu` 封装 SDK、凭据检测和连接适配；`internal/orchestrator` 定义入站领域契约，`internal/store/postgres` 实现新增入站持久化；`cmd/omnirelay` 只负责配置与装配。
- 复用 `internal/identity` 的会话与账号准入、`internal/access` 的权限/审计、`internal/directory` 的同步协议。新增 Bot 领域的 SQL 收口在存储边界，不为此重构所有历史目录 SQL。SDK 类型不得泄漏到编排或 HTTP 协议。
- 现有 `newBackend` 返回 HTTP handler 和目录服务；扩展后台生命周期时更新所有调用与测试，取消、关闭、等待退出路径必须覆盖，不遗留 goroutine。

### 必守行为

- 配置默认 version=0、enabled=false；PATCH 用 If-Match 条件更新，缺版本 428、过期 412、未知字段 400；值相同不增长版本、不生成变更审计，开关变更和审计同事务。
- 检测任务按组织、应用、凭据代次合并活动任务，Idempotency-Key 重试返回原任务。领取、续租、提交用数据库时间、版本和代次校验；历史任务不能覆盖新代次状态。GET 不请求飞书；检测只读平台接口，不发消息。
- Kubernetes Lease 只选择连接持有者；PostgreSQL 中的配置版本和连接代次负责拒绝旧持有者提交。租约丢失、停用、换代须终止旧连接并阻止晚到写入，不能仅依赖进程内布尔值。
- 心跳过期返回 unavailable；本代次成功持久化的合规真实事件才能更新 last_message_at。凭据有效、连接在线、收信成功必须独立表达。
- 入站 `(app_id, tenant_id, message_id)` 数据库唯一；事件与待路由工作同事务，去重先于容量判断，重复返回原结果。数据库提交后才确认；失败不得误确认。回调不跑模型、外部业务或发送，实测满足平台 3 秒处理限制。
- OAuth 保留 state 浏览器绑定、一次性消费和 PKCE S256。无效/过期/重放 state 为 400；仅通过事务验证的失败跳固定 cancelled/denied/unavailable 登录错误页。保留安全 Cookie、站内返回目标限制、退出及停用撤销规则。
- 目录分页与发布验证授权范围，快照完整后原子切换。临时失败保持仍获授权的旧快照；确认撤权或收窄后隐藏旧数据。未知在职状态保持 unknown；并发同步和进程恢复使用现有持久任务。

### 验证与交付

执行受影响包的 `go test`，随后 `go test ./...`；并发任务另跑相关包 `go test -race`。设置专用隔离 PostgreSQL 的 `OMNIRELAY_TEST_DATABASE_URL` 后运行数据库测试；输出含 SKIP 不能声称数据库验证通过。迁移测试覆盖空库和已有 0001–0004 的升级，运行迁移与服务保持分离。不改旧迁移校验内容。

评审材料须含改动边界、迁移/配置项、契约差异、测试命令及结果、未验证项。故障注入至少覆盖各任务指定的租约替换、重投、超时或授权撤回；具体责任见 issues 验收项。

## 前端工程师

### 所有权与基准

- 正式代码在 `web/`，Bot 页使用独立模块 `web/feishu-bot.js`；复用 `web/login.js`、`web/system-api.js`、`web/app.js` 和既有 UI 组件。不得引入新框架、替换全站布局或把原型演示数据接入正式状态。
- 实施前读取 `.agents/skills/omnirelay-frontend/SKILL.md` 并按其流程读取 Impeccable、Web Design Guidelines；以 `design/prototype/omni-relay-workbench.html`、`design/specs/omni-relay-ui-standards.md` 为基准。新 Bot 页复用已有标准表单/信息展示组件；没有确认的独立页面稿应明确标注，不能声称已通过完整页面 1:1 验收。
- 原型覆盖的布局、组件、色值、主题和动效按 1:1 复现；不擅改已确认设计。新增状态的文案使用用户语言，不暴露内部任务、租约或原始平台报错。

### 必守行为

- 复用同源 Cookie、会话和 CSRF。扩展请求工具以支持 If-Match、Idempotency-Key 与 ETag 读取时，保持所有现有调用兼容，并限制请求地址仍为同源允许路径；不能把令牌交给页面自行持久化。
- `access.admin.feishu_bot` 控制入口；管理员启停，运维可看可测。同步入口按 directory 权限展示。侧栏、移动端选择器、直达路由和登录返回白名单同步接入，进入页面时仍处理 401/403。
- 开关草稿与已保存配置分开管理；检测不保存、不清空草稿。412 刷新服务器版本后保留编辑意图，需用户再次保存，禁止自动覆盖他人配置。离开使用现有未保存提示。
- 异步请求绑定页面生命周期；切页、退出、权限撤销时停止轮询并忽略晚到响应。检测仅 queued/running 时轮询，终态停止。状态 GET 只能读取后端记录。
- 登录支持 cancelled/denied/unavailable 与旧 feishu 错误，允许重试且恢复合法原页面；回跳不等于已登录，先取 /api/v1/me。原页面无权时回工作台或展示无权状态，外部地址和未知 hash 不作为返回目标。
- 目录树/人员同 snapshot_version；409 后清除不一致结果并重载，授权撤回后及时清空旧条目及详情，不能因保留筛选继续展示撤权数据。同步失败仍区分可见旧快照与已隐藏目录；开通账号使用现有显式操作。

### 验证与交付

使用接口样例可先开发，最终必须真实 Go 接口联调。浏览器检查桌面/窄屏、浅色/深色、键盘焦点、未保存关闭、loading/empty/error/forbidden、快速切页晚到响应；登录检查减少动态效果。记录视口、路由、角色和状态，截图写入项目内。涉及 HTTP 条件头、版本冲突和快照切换的行为使用可重复自动化或固定复现步骤，不能只给静态截图。保留既有密码登录、改密和用户/角色/审计入口回归。

## 联调与验收工程师

- 负责契约样例、跨角色验收矩阵、真实预发布证据、故障演练和交付清单；实现负责人同时负责自己任务的测试，不把测试推给最后一项。
- 预发布准备同组织企业自建应用、HTTPS OAuth 回调、机器人及网页能力、消息订阅、通讯录读取范围、测试群、已开通/未开通/停用成员和运维账号；每项权限/身份字段在真实平台核实，不能只从 mock 推断可用。
- 固定官方 Go SDK 实际版本，核实启动/关闭、在线信号、超时/重投和重连；第一连接建立后再保存平台长连接方式并发布订阅。无平台权限或凭据时，提交已完成代码及可复现实验步骤，真实验收保留待验证。
- 顺序：配置读取和检测 → 真机 OAuth → 目录范围/分页 → 群 @ 和私聊入站。最后联合验证停 Bot 不影响 OAuth/目录、Web 与 Bot 同主体解析同账号、换钥不残留旧代次状态。
- 双实例/滚动更新验证连接所有权、旧代次拒绝提交、重投不重复建工作、重启恢复；撤权验证旧目录/浏览器缓存清除，失败分页验证合法旧快照仍可读。
- 记录脱敏版本、请求 ID、时间、预期/实际和通过/失败/待验证。无真实消息不得将“凭据通过”写成“已收消息”；无凭据/环境不把最终 issue 标为完成。使用专用测试群和预发布环境，真实发送与生产变更遵循单独授权范围。

## 完成定义

所有验收项有证据；运行过受影响自动测试，数据库用例未被跳过；前端有浏览器操作与状态覆盖；接口/配置文档与实现一致；凭据未泄露；过程页（若存在）写关键决策、文件、测试和剩余限制。只有长期有效知识回填模块文档。未完成项明确列出，不用 mock 通过替代真机通过。
