## 必须实施的工作

### 盘点与统一

搜索正式 `web/` 中的加载文字、spinner、busy、pending 和 progress，将每个实际等待入口列入覆盖表，注明采用的组件、请求或任务状态、成功和失败后的去向。

- 整体启动、检查或恢复会话、确需替换整块页面的首次读取：使用大页面 Loading。
- 列表、抽屉内容、角色刷新、组织目录、项目资料、文件预览等局部读取：使用紧凑 Loading。
- 登录、保存、授权、同步提交、Bot 检测启动等按钮：使用按钮紧凑 Loading，保留动作名称和业务防重逻辑。
- 重点补齐新版 `frontend/src/features/connections/feishu-bot.js` 的初次读取、保存、冲突后读取、检测排队和检测运行状态；保留配置与连接检测各自的生命周期、取消和回执。
- 后续开发的项目八栏、聊天、文件网盘等正式页面接入相同组件。当前未接通的能力显示真实状态，不为了演示而制造等待或成功。

后台刷新保留仍有权限的内容，将指示器放在工具栏或独立状态区，不清空整个容器。无数据、未接入、失权和失败均不得用持续 Loading 代替。

### 进度和结束条件

- 有真实可测量进度才传入 `progress: 0–100`。服务器只提供 queued/running 等状态时，保持未知进度条，不能按计时器或轮询次数计算百分比。
- 成环动画约 1.8 秒，与请求耗时独立。请求已完成立即展示内容；动画结束后请求仍未完成则继续显示等待条。
- 成功、失败、取消、路由切换及会话结束均需清理本次等待状态。失败保留输入、草稿、附件和真实重试入口。
- 过期请求不能覆盖新页面或清除新一轮 Loading。保留现有 AbortController、任务 ID、幂等、版本冲突与权限复核机制。
- 原型的演示进度不能接入正式数据逻辑。

### 共用组件接入方式

`markup(options)` 返回标记；`mount(host, options)` 挂载，并返回 `update` 和 `finish`。`size` 支持 `page`、`compact`、`inline`；`label` 为当前操作说明；未知进度使用 `null`。

```js
const waiting = OmniRelayLoading.mount(loadingHost, {
  size: 'compact',
  label: '正在读取文件…',
  progress: null
});
try {
  const data = await readFile({ signal });
  if (!signal.aborted) renderFile(data);
} catch (error) {
  if (!signal.aborted) showFileError(error);
} finally {
  waiting.finish();
}
```

真实任务进度变化时调用 `waiting.update({ progress, label })`。按钮用 `OmniRelayLoading.button(button, true, '保存中…')` 开始，用 `button(button, false)` 恢复；该方法只控制视觉与 busy 标记，禁用、防重复提交和恢复可用性由原业务逻辑管理。原有加载内容所在宿主与正文分别管理，避免刷新时丢失阅读位置。

### 视觉与可访问性

保留选定的紫色与青绿色 Logo 几何和配色。页面、区域与按钮跟随同一主题；窄屏等比收缩，避免水平溢出。

减少动态模式显示完整静态 Logo 和静态等待条；页面隐藏或组件离屏时暂停动画。Loading 不抢焦点，等待说明与进度条应有可访问名称；未知进度不提供虚假的 `aria-valuenow`。完成后清理宿主的 `aria-busy`。
