# 项目 PM 业务工具与权限设计

设计目标是让成员以自己的身份，通过本项目的 PM 查询资料、协作处理任务。工作台、个人 API Key、群内 @Bot 与私聊共用 Go 业务授权。项目 PM 在 DSH 中加载当前 Gateway 提供的业务工具。身份工具 `context_whoami` 单独保留。工具目录由 Go 提供，Gateway 在每次回调时校验真实账号、项目、工作、实例归属、执行代次及轮次。

## 一、角色与资源范围

| 身份 | 授权口径 |
| --- | --- |
| 正式项目成员 `member` | 可查本人在项目内可见的资源、创建任务、维护允许修改的任务、追加进度记录。建议新建任务默认负责人为本人 |
| 只读成员 `reader` | 保留现有只读角色，可以执行可见性范围内的查询 |
| 任务编辑者 `editor` | 继承普通成员能力，可在本项目分派、维护其他成员的任务。编辑者身份本身不授予项目档案、成员或群管理权 |
| 项目经理 `manager` | 可管理本项目档案、成员、项目群关联和任务 |
| 管理员 | 建议纳入本项目有效委派的 `project_admin`，以及已有本项目有效会籍的 `system_admin`。二者均须按明确的项目动作授权。未入项系统管理员的跨项目管理、首位经理任命沿用独立管理入口 |

项目 PM 的服务端上下文固定租户、应用、调用人、项目、会话和原回复目标。问题中提到另一个项目，或者传来另一个项目的对象 ID，都不能改变当前空间。目标成员、负责人、群和任务可作为业务参数，调用人身份与项目范围由 Gateway 从可信入口注入。项目管理员是一项委派，可以与成员基础角色并存；委派到期或会籍换代后重新核验。

## 二、能力清单

| 资源 | DSH 工具拟名 | 输入与结果 | 权限 |
| --- | --- | --- | --- |
| 项目基本信息 | `project_get`、`project_update` | 读取名称、阶段、背景、计划日期等。更新仅接受允许变更的字段和已读取版本；改计划日期不会修改成员或群设置 | 成员可读；经理、管理员可改 |
| 项目成员 | `member_list`、`member_add`、`member_set_role`、`member_remove` | 按姓名或角色查正式成员；增删或改变本项目角色。重名时先返回候选。系统角色、平台账号启停不属于项目成员变更 | 成员可查；经理、管理员可管理普通项目成员。保护最后一位有效经理；经理任免和管理员委派继续检查对应的委派权限，禁止自行提权 |
| 项目群聊 | `chat_list`、`chat_search_messages`、`chat_bind`、`chat_unbind`、`chat_set_primary` | 查关联群、主群与可见历史；维护本项目的绑定和主群。绑定只接受可管理、可访问的候选群，已属其他项目则转交显式迁移流程校验两端 | 成员可查本人有权访问的群和消息；经理、管理员可维护绑定，仍需原渠道授权 |
| 项目文件 | `file_search`、`file_get` | 按关键词返回可见文件及授权入口；详情或内容摘要再验来源读权。筛选后计算总数，下载或预览沿用鉴权入口 | 项目会籍和文件来源读权均有效时可查。角色本身不解锁受限文件 |
| 项目任务 | `task_search`、`task_get`、`task_create`、`task_update`、`task_transition`、`task_add_progress` | 检索、详情、创建、修改业务字段、变更状态、追加带作者和时间的进度说明。每个写操作独立鉴权 | 见下表 |
| 项目日报 | `daily_report_query` | 按业务日期或日期区间查询。区分本人日报、当前账号可见的成员日报和已获准向项目发布的简报，返回来源和日期 | 普通成员可查本人日报及允许其查看的简报；管理者按项目日报读权查团队记录。按可见记录计算统计 |

“群聊修改”第一版具体指项目群绑定、解绑和主群设置。如果产品也要改平台群名、群公告或拉人退群，应增加相应的独立动作，并同时检查项目管理权、平台操作权和 Bot 可用权限。Agent 回复当前话题、定时发给已授权对象继续使用既有 Channel 交付路径。

### 任务写入边界

以下为普通成员任务编辑范围的建议基线。项目经理和具有任务管理权限的管理员、编辑者，可在本项目维护或分派任务。

| 操作 | 普通成员 | 执行约束 |
| --- | --- | --- |
| 查询、创建 | 可查本项目可见任务；可新建本人负责的任务 | 创建自己的任务无需分派权；指定他人为负责人、修改参与人或改派任务单独检查分派权 |
| 修改字段 | 可修改本人负责或参与的未终结任务的标题、说明等协作字段 | 字段白名单按动作和资源返回。负责人、参与人、优先级等分派或调度字段单独授权；资源版本过期时返回冲突 |
| 更改状态 | 可推进本人负责或参与的未终结任务 | 沿用看板合法流转。“受阻”需原因；取消、重开已完成或已取消任务需任务管理权和原因 |
| 补充进度 | 可对本项目可评论的任务追加进展说明，包括他人负责的可见任务 | 追加至任务活动，保存实际作者和时间。文字“已做完联调”只追加记录；明确要求“把状态改成已完成”再执行状态动作 |

例子：小林说“建一个接口联调任务”可以直接以本人为负责人创建。“把张工的任务改派给小陈”要求分派权。“在张工任务下补一句：测试用例已准备好”走进度追加。三个请求使用不同的授权判断。

## 三、一次调用如何落地

1. **Gateway 建立身份与范围。** 从会话、个人密钥或已验证的渠道事件取得实际账号，检查账号状态和项目会籍。Runtime 得到绑定本次工作的工具目录；名称、同名对象或操作意图不清时，先解析对象或追问。群消息、文件正文里的指令只作待分析的内容。
2. **Go 逐次检查动作。** Runtime 经双向 TLS 回调 Go。Go 依据本轮绑定恢复调用者、项目和角色，查询具体资源是否在本项目、调用者可读哪些字段、可做哪些变更。工具列表能指导模型选择动作，最终授权由业务服务执行；工作台、API 和 Agent 使用同一策略。
3. **写入可重试。** 在同一事务里复核会籍代次、角色、对象归属和所需版本，完成业务变更、记录实际操作者与幂等回执。每个逻辑动作有稳定标识，重试同一动作复用回执；同标识不同参数返回冲突。Runtime 将工作内的命令序号和待确认请求写入持久卷的 SQLite 日志，重启后先向 Gateway 核对待确认写入。任务更新使用任务版本，涉及看板移动时同时检查看板版本。不用模型生成的文字推断写入成功。
4. **按受众返回结果。** 工具取数时就把结果限制在本轮受众可见的范围，避免模型先读私密字段再自行删减。发布前再次复核。个人工作台可展示本人获准读取的详情；群话题只返回可证明对该群可见的信息。无法证明群可见时，只提示发起人在个人工作台查看。仅将非敏感的状态与必要链接写入回执；回复带上 PM 名称和项目空间。

## 四、接入前的实现基线

- 当前创建任务走 `project.assign`。普通成员只能推进本人负责或参与的任务，不能改一般任务字段。新增“成员创建”和“成员修改协作字段”两项领域授权，保留分派与终态管理权。复用现有任务版本、评论、活动历史及重试机制。
- 现有项目档案和群关联主要检查 `project.settings`。已有成员维护走 `project.delegate`，当前实现授权项目经理；无有效经理时有单独的首位经理指派路径。按本设计允许管理员维护成员，需要在 Go 授权层明确补齐管理员能授予哪些项目角色，避免把系统级角色管理权带入项目 Agent。
- 当前执行回执围绕一次只读身份工具。接多工具时需按工作、轮次、逻辑动作分别记录执行结果和业务对象版本，使一次“查询任务后更新状态”以及中断后续跑都能正确对账。超时先查询已有回执，再决定是否重试。

## 五、跨工具验收门槛

| 场景 | 通过条件 |
| --- | --- |
| 成员、编辑者、经理、管理员、只读、非成员走同一接口 | 每类账号按矩阵执行；直接调用工具也不能跳过后端授权。其他项目的任务、成员、群和文件 ID 不泄露对象存在性 |
| 资料可见性及群内回复 | 所属项目相同、来源权限不同的两人查询同一文件，结果按人过滤。管理者能看某份个人日报，群里提问仍不返回私人正文 |
| 写任务、变更权限与失败恢复 | 同一创建请求重试只建一项任务，进度重试只追加一次。旧版本修改返回冲突；写入前降权导致事务拒绝；写入后交付前撤权则保留业务事实并抑制敏感回复 |
| 项目管理动作 | 普通成员和编辑者修改档案、成员或群绑定均被拒。获授权管理者成功，最后一位经理不能被移除；跨项目群绑定不能被一侧的项目 PM 擅自迁走 |

内部门槛使用隔离 PostgreSQL、项目 Bot 工作台、内部群 Channel、双向 TLS 和真实 DSH 镜像。模型端使用可重复的测试响应。身份查询仍在群内直接署名回答。业务请求由发起人的项目 PM 执行，详细结果进入发起人的项目 Bot 工作台，原群话题收到带署名的查看提示。全局私聊查询助手和定时提醒有各自的工具目录。

## 六、每个工具的功能与权限验收

以下每一行都对应 `TestProjectPMToolMatrix` 中的同名子测试。增加工具时，目录和已覆盖用例名称必须完全一致。每个工具都要拒绝没有本项目会籍的系统管理员；管理写入还要分别拒绝普通成员、只读成员和任务编辑者。返回拒绝时事务回滚。

| 工具 | 功能通过条件 | 权限通过条件 |
| --- | --- | --- |
| `project_get` | 返回北辰项目名称、状态和版本 | 只读成员可查，不能以工具参数切换项目 |
| `project_update` | 指定字段生效，版本递增；旧版本冲突 | 经理、有效委派管理员、已入项系统管理员可改；委派换代后拒绝 |
| `member_list` | 按角色或姓名筛选有效会籍，返回账号、成员 ID 和会籍代次 | 项目成员可查，调用者不能指定另一个项目 |
| `member_add` | 为目标账号建立有效会籍，重复添加报告冲突 | 经理或项目管理员可添加普通角色；委派管理员不能任命经理 |
| `member_set_role` | 以当前会籍代次变更角色，旧代次不能覆盖新角色 | 普通成员与编辑者不能管理成员，管理经理角色须另验委派权 |
| `member_remove` | 按代次撤销目标会籍及其本地来源读权 | 只允许具备管理权者；保护最后一名有效经理 |
| `chat_list` | 返回可见群、绑定版本及主群版本，候选群可按 ID 核验 | 原渠道不可见的群不返回，查询绑定候选还须项目设置权 |
| `chat_search_messages` | 用关键词或完整业务日期区间检索，也可组合使用。日期含首尾两天，按项目时区计算。结果给出群、消息 ID、发送和更新时间、已知发言人、命中片段及分页标志 | 要求本项目绑定和本人的群来源读权，仅返回已索引、可见、未撤回的文本 |
| `chat_bind` | 按观察到的版本绑定可访问候选群 | 要求项目设置权及来源权限；禁止将另一个项目的群迁入 |
| `chat_unbind` | 解除当前绑定，清理关联主群及相应投递配置 | 要求项目设置权与原渠道授权；只能解除当前项目的绑定 |
| `chat_set_primary` | 同时校验绑定和主群版本，返回新主群 | 仅可设置本人有渠道权限且已归属本项目的群 |
| `file_search` | 按词列出授权文件、稳定引用及筛选后的计数 | 项目经理也看不到未向本人开放的文件 |
| `file_get` | 根据引用取得本地文件摘要或云文件元数据及鉴权入口 | 再验单份文件来源；撤权后工具和历史回复均不返回正文 |
| `task_search` | 按关键词、状态、负责人和页码返回匹配任务 | 只读成员可查本项目；不能通过参数扩大范围 |
| `task_get` | 返回任务字段、任务版本和看板版本 | 不同项目的任务 ID 与不可见任务采用相同拒绝结果 |
| `task_create` | 默认由本人负责，保存真实创建人；重试只创建一次 | 普通成员可建自己的任务；指定他人须分派权；只读成员拒绝 |
| `task_update` | 修改指定字段，保持其他字段；校验任务版本 | 普通成员只可改本人负责或参与的未终结任务的标题、说明；改派须分派权 |
| `task_transition` | 更新状态，受阻需原因；旧任务或看板版本冲突 | 普通成员可推进本人负责或参与的未终结任务；取消和重开须任务管理权 |
| `task_add_progress` | 追加含作者、时间的活动；重试不产生第二条记录 | 可评论成员可为他人的项目任务补充进度，只读或非成员拒绝 |
| `daily_report_query` | 按业务日期查询日报；`source=published` 返回仍已授权展示的已发布统计 | 普通成员只看本人日报，管理者可看团队日报；已发布统计仍校验目标群可见性 |
| `briefing_list` | 在已撰写简报中按日期和关键词分页查题目、摘要及当前版本。生成和群发布记录单独查询 | 项目成员可读，本次授权的项目决定范围 |

运行 `bash tests/integration/group-agent-gate.sh`。脚本检查实际通过标记，跳过不会计为通过。除工具矩阵外，`TestProjectToolRecoveryGate` 校验并发重试、回执参数冲突、旧工作代次与撤权；`TestProjectToolHistoryGate` 校验交付前及交付后撤权、后续模型会话隔离；`TestProjectToolAudienceImageGate` 用真实镜像在群内创建任务，检查原话题、私人成果与另一成员隔离。生产开关和外部平台发送独立验收。

涉及来源授权的历史答复按产生时的数据重新核对，数据变化后可能需要重新查询。项目 PM 的人设目录独立保留，读取受限资料后，下一次工作台请求使用新的模型会话，以免旧正文进入新一轮提示。

## 项目成员与任务管理补齐

网页与项目 PM 插件共用领域命令。成员的 `role` 决定访问权限，`role_title` 为本项目业务角色名称，`responsibility` 为职责描述。后两者的修改递增资料版本但不改变权限代次；访问角色变更同时换代。成员资料查询返回 `version`，网页与 `member_update` 写入要求匹配，旧版本返回冲突且不覆盖草稿。移除仍负责或参与未完成任务的成员前须先交接。

| 新增工具 | 通过条件 | 权限 |
| --- | --- | --- |
| `member_candidates` | 按姓名或账号分页查询启用且尚未入项的账号，仅返回必要身份字段 | 项目设置权 |
| `member_update` | 按版本修改访问角色、业务角色或职责，未提供的字段保持不变 | 项目设置权；负责人任免继续校验委派权 |
| `task_delete` | 按任务版本和明确原因逻辑删除；保留活动、来源及审计；退出看板、搜索和详情 | 任务分派管理权 |

`task_create` / `task_update` 同步支持开始/截止日期、验收条件、里程碑、参与人和标签。可选关联用空字符串清空，数组用空数组清空；普通成员的协作字段与分派字段边界沿用领域校验。网页新建复用原型任务编辑器，成员管理复用标准右侧抽屉。删除使用二次确认和原因，服务端按请求键记录幂等回执。

### 与新版任务工作区共用的操作

项目对话按轮次从 Gateway 加载目录。看板与列表共享业务数据，显示模式、字段显隐、抽屉收起和滚动位置由浏览器保存。

| 操作 | 工具 |
| --- | --- |
| 看板版本、列、标签、筛选和续页 | `task_board_get`、`task_query` |
| 任务权限、本人互动与手动参与人 | `task_actions`、`task_get`、`task_update` |
| 调整状态、取消和重开、跨列移动、列内排序、批量编辑 | `task_transition`、`task_move`、`task_bulk_update` |
| 列配置、设置默认列与列迁移、业务时区 | `task_board_save`、`task_business_time`、`task_board_timezone` |
| 创建、修改和删除标签 | `task_tag_create`、`task_tag_update`、`task_tag_delete` |
| 任务评论、变更历史、附件或文档来源 | `task_add_progress`、`task_activity_list`、`task_evidence_list`、`task_evidence_link`、`task_source_tasks` |
| 成员进展反馈与审核 | `task_feedback_list`、`task_feedback_submit`、`task_feedback_review` |
| 从授权项目资料或群消息提取候选 | `task_candidate_sources`、`task_candidate_chat_sources`、`task_candidate_submit` |
| 候选筛选、确认、合并或忽略 | `task_candidate_list`、`task_candidate_review` |
| 新建与查询任务里程碑 | `task_milestone_create`、`task_milestone_list`，使用 `task_update` 关联或移除里程碑 |
| 删除任务 | `task_delete`，需任务管理权、当前版本和明确删除原因 |
| 标记项目会议纪要 | `meeting_mark` 使用 `file_search` 返回的文件引用。调用人需要项目分派权和该文件的阅读权 |
| 按业务日期维护项目简报 | `briefing_list` 发现已保存的日期及当前版本，`briefing_get` 读取成员共享的标题、正文和版本。拥有项目设置权限的成员使用 `briefing_save` 写入，首次版本为 0，后续携带读取的版本 |

普通成员可在权限范围内维护本人任务或提交反馈。管理者取消任务或重新打开终态任务时提供变更原因，批量更新按任务版本整体提交。确认候选并共享前需取得用户确认。来源、反馈和候选读取沿用当前项目与当前成员权限。

项目周报按 `task_business_time` 返回的项目业务日期和时区取证。群检索按发送时间截取日期范围，每页 25 条，`has_more` 表示同一筛选还能继续翻页。群消息只能证明相应发言；落地、上线和验收结果需各自的凭据。任务当前状态和期间变更分别取自任务详情与活动。内容和来源相矛盾或覆盖有限时，报告保留实际查阅范围和待核实事项。起草只返回正文，明确保存后才写入项目共享简报，投递凭据另查。

有取证期间时，Gateway 将模型请求的日期与业务期间求交，并持久化实际读源参数。会议文件按本地来源登记时间或飞书分享时间筛选。报告中的会议发生日期须来自纪要正文或其他可核实的带时间记录；仅有登记或分享时间时，报告列明实际可确认的资料接收日期。用户点名的跨期文件可作为标注日期的参考资料。期间内无简报时，`briefing_list` 仍附上全项目最近成稿的日期、标题、版本和总数；区间外归档目标的 `briefing_get` 只取业务日期和版本用于并发保存。
