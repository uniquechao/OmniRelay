# OmniRelay 本轮需求改动与开发交接

2026 年 11 月 19 日 · v1.0 · 面向产品、前端、后端、飞书集成和测试团队

请开发团队按本文件的需求编号拆解开发任务，并以对应原型和验收场景核对交付。本轮集中完善组织树、飞书导航与聊天记录、文件网盘，以及参考 OmniGrid 的项目工作台和任务编辑。当前可运行原型承载页面与交互演示，生产实现进度需要团队另行核对。

## 1 范围与使用方法

### 会话起止范围

本文件从以下反馈开始整理，覆盖其后到本轮交接请求之前的需求与修改。

### 交付状态

- **已确认需求**来自本段会话中用户明确提出或修正的要求，可用于拆解。
- **原型已演示**表示当前本地 HTML 中存在可操作的页面或示例，正式数据、权限、服务接入和部署状态仍需单独确认。
- **实施建议**用于补齐真实产品的数据和接口行为，供团队评审。
- **待定口径**尚无用户明确确认，例如临期阈值、Office 预览保真程度和多维表格同步范围。

文档中的任务编号用于追踪需求。实现方可将一个编号拆成前端、后端、集成与测试子任务。本文未创建项目管理系统中的实际 issue，也未安排负责人和工期。

## 3 组织树与人员组件

### UI01 组织树操作重新设计

**已确认需求**

- 分支使用展开箭头表达展开和收起，父节点与叶节点在缩进、图标、行高和选中态上保持一致。
- 批量操作使用“展开全部”“收起全部”的明确含义，替换容易误解为增删节点的 +、−。
- 组织树作为可复用组件，供组件演示、组织选择和相关组织筛选复用。
- 手动展开分支时收起其他同级分支是前序已提出的交互，在本轮原型中继续保留。

**原型已演示**

树内工具区提供文字批量按钮。手动展开分支会关闭同级分支，全部展开可同时打开所有分支。可选择树显示当前选择路径。

**验收**

展开按钮操作不会创建或删除组织；批量展开、批量收起和单分支操作均正确；选中组织后可以回看完整路径；键盘可访问节点及工具按钮。

### UI02 聊天人员统一展示

**已确认需求**

- 会话列表、群成员、会话标题和消息中的同一人员使用一致的圆形头像和固定配色。
- 姓名与组织路径保留字号层级，长文字省略，悬停显示完整内容。
- 聊天页按其他页面的密度缩小头像、工具图标和文字。
- 点击人员头像或姓名，在点击位置附近浮动显示基本信息。后续浮动卡片要求覆盖先前点击直接打开个人详情抽屉的交互。
- 任务卡片顶部只显示负责人头像，悬停可看完整姓名。

**原型已演示**

人员浮动卡片显示姓名、所属组织和飞书身份来源；点击空白处或 Escape 可关闭。头像使用稳定人员标识计算配色，缺少标识时按姓名回退。

**验收**

跨会话同人同色；卡片不会超出屏幕；点击姓名和头像都可打开；任务卡片不重复显示头像内外两份姓名。

## 4 系统管理菜单与已有 Bot 接入

### SYS01 菜单归位

将“连接设置”和“飞书 Bot 配置”置于“系统管理”下，桌面与手机导航一致。进入子页正确展开父菜单并显示当前选中状态，旧连接设置链接继续可到达对应页。

### BASE01 已有飞书 Bot 配置

**前序能力依赖**

提供飞书 Bot 配置入口。配置、Bot 自身可用性验证和权限联调分别可操作。

**原型字段与交互**

App ID、App Secret 引用、启用状态、接入方式和保存状态。配置发生修改后可保存；验证使用已保存的示例配置。原型接入方式为飞书长连接，密钥使用部署端引用名。

**实施建议**

复用正式系统的凭据管理、连接设置和审计能力。前端展示脱敏值，配置保存与验证分别返回结果。

### BASE02 已有 Bot 自身可用性验证

按钮明确为“验证 Bot 可用性”，可在未选择项目时执行。检查应用凭据、机器人能力、长连接与事件订阅、消息权限，逐项展示执行中、通过或失败及具体原因。

**原型已演示**

通过模拟环境切换正常、凭据错误、机器人能力未启用、连接失败、订阅缺失、权限缺失等场景。

**验收**

界面能区分应用配置可用与具体项目操作获准；失败项可以定位；重新验证不会保留前次成功假象。

### BASE03 已有权限联调验证

选择测试账号、目标项目、操作及群内信息范围后验证。原型操作包括查询共享任务、分派任务和管理简报发布。结果包含 Bot 与目标群的关系、账号状态、项目权限和结果可公开范围。

**实施建议**

正式验证复用实际授权判断；只验证权限的动作应显示检查结果，需要实际发消息的测试动作单独注明目标和结果。

**验收**

账号停用、缺少项目授权、Bot 不在目标群或内容不能对群公开时显示对应失败原因；失败不被表述为业务操作已执行。

## 5 飞书机器人记录与聊天交互

### CHAT01 全局会话列表与消息阅读

**已确认需求**

- 展示 Bot 所在群聊，以及 Bot 和员工的 1:1 会话。
- 双栏布局，左侧会话列表，右侧当前会话消息；会话列表和消息区各自滚动。
- 保留搜索、群聊与 1:1 筛选、同步状态、同步详情与刷新入口。
- 消息显示发送人、时间、正文和 Bot 回执。任务查询、任务分派和项目简报回执可进入对应项目内容。
- 标题栏提供群成员与会话内搜索入口，使用带悬停提示的图标按钮。
- 人员样式和浮动信息卡按 UI02。

**验收**

切换会话后标题、消息、成员和搜索范围一致；群聊和 1:1 正确筛选；消息搜索能定位结果；回执深链可打开任务或简报。

### CHAT02 群聊项目归属与项目主群

**已确认需求**

- 群聊可以手动选择、修改和清除所属项目。
- 归属信息放在群聊头部，修改入口使用图标；点击后弹出可搜索的下拉选择框。
- 在项目群聊中提供“设为项目主群”和“修改项目归属”两个图标操作，悬停显示提示。
- 项目主群在群名后显示黄色实心星标。
- 当前原型每群归属一个项目，每项目最多一个主群。“文件可属于多个项目”的要求单独应用于文件。

**原型已演示**

群聊改绑后从原项目关联群列表移到新项目；切换主群会替换原主群。归属和主群在浏览器本地保存。作为主群的群移走后，原项目当前主群记录会清空。

**验收**

全局机器人记录与项目内群聊显示同一份群归属；旧项目与新项目的群列表同步更新；主群唯一；修改和清除后刷新可核对结果。

### CHAT03 消息分栏可拖动

双栏中间增加可左右拖动的分隔栏。左右区域随拖动一宽一窄，整个聊天区宽度保持稳定。保留双方最小可用宽度，悬停仅显示克制的细线提示。

**原型已演示**

支持鼠标拖动、键盘方向键、Home/End 和本地宽度记忆。手机单栏交互中隐藏拖拽柄，使用会话列表与消息详情往返。

**验收**

连续拖动、刷新恢复、窗口变窄、切换主题和手机返回均可用；拖动不会改变当前会话或丢失输入草稿。

### CHAT04 参考飞书的发送框

**已确认需求**

聊天区底部增加发送框，参考飞书的输入框与紧凑工具排列。工具包括文本格式、表情、@ 成员、附件、展开输入框和发送。

**原型已演示**

文本输入、加粗和斜体、表情选择、成员提及、附件文件名、展开和收起、Enter 发送、Shift+Enter 换行。中文输入法组词阶段 Enter 不触发发送。切换会话保留各自未发送草稿。

**实施建议**

真实发送需要明确发信身份和收件目标。发送按钮应显示可操作或失败原因，发送中防止重复提交；成功、失败与未知回执分别呈现。

**验收**

空消息不可发送；文字和附件可以一起提交；消息发送到当前会话；发送失败保留输入和附件；实际飞书消息标识与界面消息可对账。

**当前边界**

原型消息在本页会话内演示；选择附件仅演示文件名，尚未上传或发给飞书。刷新后演示发送消息和输入草稿重置。

## 6 项目工作台

### PROJ01 参考 OmniGrid 的项目结构

**已确认需求**

参考 OmniGrid 项目功能设计需求并形成原型。项目工作台固定八个栏目，项目概览、成员、群聊、会议纪要、文档、日报、任务、飞书 Bot。

**原型已演示**

项目列表可进入项目；页签和旧简报链接可到达对应栏目；概览节点、群消息、纪要和文档中的关联任务可以进入任务详情。

**实施说明**

各栏目完整业务需求已有独立项目需求稿。静默成员、负责人交接、项目记忆、正式资料同步等属于该稿的后续实施范围，不能据栏目存在判断已经完成。

### PROJ02 项目群聊与全局记录统一

项目“群聊”复用机器人记录的会话列表、消息阅读、搜索、人员浮动信息和发送框。只显示属于当前项目的关联群。移除项目群聊标题区原先的“机器人记录”跳转按钮。主群和改绑交互按 CHAT02。

**验收**

项目 A 与项目 B 的会话列表不会混入对方群；全局记录和项目内阅读同群时消息、归属一致；主群星标及时更新；深链可回到指定群。

### PROJ03 日报和项目 Bot

日报分为“成员日报”和“项目简报”，旧简报入口落到后者。项目“飞书 Bot”显示本项目目标群、接入状态、每日简报计划、接入验证和最近回执；全局应用配置继续从系统管理进入。

**验收**

成员日报提交、简报生成和消息送达能够分辨；查看简报可核对目标群和时间；项目接入与全局应用状态分别展示。

## 7 任务卡片与里程碑

### TASK01 任务卡片参考 OmniGrid

**已确认需求**

- 默认四列为待开始、进行中、受阻、已完成，看板与列表可切换。
- 卡片顶部为任务编号和负责人头像；头像外侧重复姓名去掉，悬停头像显示完整姓名。
- 优先级和标签采用紧凑样式，随后显示任务标题、受阻原因、里程碑和日期。
- 紧急、重要、普通和低优先级使用不同卡片底色和边框，颜色按 OmniRelay 色彩系统适配。
- 受阻原因在受阻任务标题下显示，长标题按 OmniGrid 卡片密度处理，当前原型最多两行。

**验收**

不同优先级可通过文字、颜色和边框共同辨识；窄列标题不挤出卡片；卡片点击可进入编辑；拖动后编号和内容保持对应。

### TASK02 临期提醒

未完成的临期任务，日期加红并增加红色感叹号。已完成任务不显示临期告警。看板、列表、概览节点采用一致的判断口径。

**当前原型默认**

以示例日期 2026-11-18 为计算基准，截止前 3 个自然日内及已逾期的未完成任务显示红色告警；卡片日期为月/日。

**待定口径**

3 天阈值来自原型默认选择，需产品确认。正式实现应按当前业务日期与项目业务时区计算，并定义当天到期、逾期、无截止日期和跨年的展示。

### TASK03 里程碑关联与筛选

每个任务可关联一个里程碑，卡片与列表显示里程碑。任务详情可修改里程碑，工具栏可筛选全部、指定里程碑或未关联；与搜索、负责人筛选共同生效。

**验收**

修改里程碑后卡片和列表更新；当前筛选不再匹配时任务退出结果；看板与列表切换保留里程碑筛选；跨项目切换不会串用里程碑选项。

## 8 任务编辑复刻 OmniGrid

### TASK04 编辑页面与字段

用户明确要求支持任务编辑，参考 OmniGrid 任务页 1∶1 复刻。对照范围包含页面结构、字段、交互、评论动态、保存与关闭行为，并沿用已确认的 OmniRelay 主题。

顶部显示项目、任务编号、任务名称路径，以及“保存任务”和收起按钮。左侧编辑正文，右侧属性栏编辑结构化信息，评论位于动态上方。任务详情在工作台内容区域展开，项目标题和页签保留上下文；手机按窄屏重新排列。

| 编辑项 | 行为和校验 |
| --- | --- |
| 标题 | 可编辑，不能为空 |
| 正文 | 多行编辑，保留换行 |
| 状态 | 待开始、进行中、受阻、已完成、已取消 |
| 优先级 | 紧急、重要、普通、低优先级 |
| 主负责人 | 搜索选择，支持姓名及拼音；自由输入需选中有效结果才可保存 |
| 开始日期和截止日期 | 可修改，截止日期不能早于开始日期，支持无日期 |
| 里程碑 | 选择当前项目里程碑或未关联 |
| 标签 | 添加和移除，可多选 |
| 验收条件 | 在“验收与参与人”中编辑 |
| 参与人 | 搜索多选，保存稳定人员标识 |
| 受阻原因 | 进入受阻状态必须填写 |
| 完成结果 | 完成状态或已有结果时可编辑 |
| 变更原因 | 取消任务、重新打开已完成任务时按正式规则填写 |
| 创建与更新信息 | 显示创建人、创建时间、更新时间、版本与更新人 |

优先级标签需建立与 OmniGrid 正式枚举的映射；当前原型使用紧急、重要、普通、低优先级，不应直接把展示字符串当作接口枚举。

### TASK05 保存与草稿保护

- 没有修改时，“保存任务”禁用；字段变化后可提交。
- 保存成功后保留任务详情打开，卡片、列表和相关节点回显最新内容。
- 关闭、Escape、点击详情外空白或切换页面时，有未保存内容则提醒保存并关闭、不保存或继续编辑。
- 校验失败就近展示错误，定位到对应字段，保留草稿。
- 编辑不会改变任务稳定标识。评论和历史跟随原任务。
- 正式多用户写入需要版本核对，冲突时保留草稿供比对。

**原型已演示**

字段编辑、校验、保存后继续编辑、未保存提醒、切页草稿保护，以及浏览器本地持久化。正式保存服务、并发冲突和跨账号一致性仍需接入。

### TASK06 评论与动态

评论输入区位于动态上方，采用单一外框和内部发送按钮。动态提供全部、修改记录和评论筛选，修改记录保留字段前值与后值，显示操作者和时间。新内容按最近在前排列。

**验收**

空白评论不可提交；发送后评论进入当前任务动态；只查看评论或修改记录时过滤正确；保存标题、负责人、日期等字段后能找到对应变更；关闭重开和刷新后正式记录可读取。

**原型已演示**

本地评论、字段变更记录和筛选。正式动态分页、操作者身份、审计与服务端时间需要接入。

### TASK07 OmniGrid 完整性核对

“1∶1 复刻”应以实际 OmniGrid 任务详情为核对对象。当前原型已覆盖主要编辑字段和评论动态，以下正式能力仍需团队结合源组件补齐或明确实施范围。

- 提炼依据、原始消息或资料来源，以及无权读取依据时的状态。
- 进展反馈与审核面板。
- 当前账号的可编辑字段、负责人本人操作范围和只读状态。
- 多人编辑时的版本冲突、读取最新版本与保留草稿。
- 动态分页及真实操作者、版本、服务端时间。

这些内容可从 ProjectTaskInspector、ProjectTaskEvidence、ProjectTaskFeedback 和 ProjectTaskActivity 继续拆解。原型保存成功不代表上述正式能力已经实现。

## 9 飞书文件网盘

### FILE01 当前范围与分类

“飞书 → 文件网盘”先实现统一飞书文件列表，分类为全部、会议纪要、飞书文档、任务表格（多维表格）和文件。列表复用现有标准搜索、筛选、排序、分页、总数和每页条数。

用户在讨论后收窄了范围。新建 Space、主动上传团队文档、空间成员和目录管理暂缓，后续如恢复需要重新评审。

### FILE02 列表字段与格式图标

| 字段 | 展示和操作 |
| --- | --- |
| 名称 | 文件名称、格式标识，点击可预览 |
| 分类 | 四种业务分类之一 |
| 来源 | 群聊与分享人，可点击定位分享消息 |
| 所属项目 | 显示一个或多个项目标签，点击编辑 |
| 大小 | 展示容量及单位 |
| 操作 | 预览 |

PDF、Word、Excel、PowerPoint、ZIP、飞书文档、多维表格和妙记分别使用对应格式图标和识别色，替换所有格式共用一种文档图标的旧效果。聊天中的文件消息也应一致。

**待定口径**

云文档、纪要和多维表格的“大小”应注明采用原始文件大小、已同步内容大小还是导出大小；未知时显示明确占位。当前容量值均为示例。

### FILE03 来源定位到具体消息

点击来源直接进入对应群聊，自动滚动到分享该文件的消息，并高亮目标。手机自动打开消息区。保存稳定会话 ID、消息 ID 和文件 ID，刷新或更换文件归属后仍能定位原始分享。

**验收**

从列表和预览详情点击来源均能到达同一条消息；同群多份文件不串位；文件改归属不改写原始来源；源消息不可读或已删除时显示对应状态。

### FILE04 文件多项目归属

**已确认需求**

一个文件可以属于多个项目。点击所属项目打开可搜索多选框，支持新增、逐项移除和保存，列表及预览详情即时回显。

按任一已归属项目筛选时均可找到同一文件。项目标签使用项目稳定 ID，项目重命名不丢失关联。

**验收**

将同一验收文件同时归到北辰和启明，分别筛选两个项目都能找到；移除启明后，北辰关联和原分享消息继续可查；关闭未保存弹窗时提醒处理草稿。

**实施建议**

使用文件与项目的关联表维护多对多关系，同一文件与同一项目只保留一条有效关系。文件归属与群聊归属分别维护。

### FILE05 内容采集与存储

用户最初明确要求群中提到的飞书文档“内容拉取过来存储”，以及归集群内传输文件。后续简化为飞书文件列表时保留这一内容读取诉求，需在正式开发中接通。

保存文件元数据、可读取正文或原文件、同步状态与更新时间，同时保留原消息来源。相同云文档重复分享应关联多个分享记录，避免把一次分享错误地当成一份独立正文。

**实施建议**

按来源授权采集；支持重试、部分内容、源更新和撤权处理。正文与原文件保留版本或更新时间依据，预览能够说明当前读取的是哪个已同步版本。

### FILE06 文件预览

常见格式提供查看能力。原型以右侧加宽抽屉演示，列表上下文保留，抽屉内显示分类、来源、所属项目、大小和正文。

| 格式 | 期望查看能力 |
| --- | --- |
| 飞书文档和会议纪要 | 阅读已同步正文 |
| 多维表格 | 查看同步的表格内容 |
| PDF | 页内容预览 |
| Word | 文档内容预览 |
| Excel | 表格内容预览 |
| PowerPoint | 幻灯片内容预览 |
| ZIP | 展示目录，并查看其中支持格式的内容 |

**当前边界**

原型正文、Office、PDF、表格和 ZIP 均使用手写示例内容，没有实现真实文件解析、Office 转换或 ZIP 解压。ZIP 示例展开后显示文本内容，不等于已支持任意内嵌 Office 文件的真实预览。

**待定口径**

Office 需内容阅读还是版式保真、Excel 工作表范围、多维表格字段与分页范围、扫描 PDF 是否 OCR、加密 ZIP 和不支持格式如何展示，由团队评审确定。

## 10 数据关系与正式接入

| 对象 | 主要关系和一致性要求 |
| --- | --- |
| 人员 | 稳定人员 ID 对应姓名、组织与头像配色 |
| 项目 | 关联成员、任务、里程碑和群；八栏使用同一项目 ID |
| 群聊 | 当前需求为一个项目归属，可清除；同项目最多一个主群 |
| 消息 | 绑定原会话和发送人；文件来源定位使用稳定消息 ID |
| 文件 | 可被多个消息分享，也可归属多个项目；来源与项目标签独立 |
| 任务 | 关联项目、负责人、参与人、里程碑、标签、版本、评论和动态 |
| Bot 配置与联调 | 全局应用配置、Bot 运行状态、目标群关系和项目操作权限分别记录 |

现有架构稿建议 OmniGrid 持有正式项目、成员和任务，OmniRelay 持有接入、运行和交付记录。用户要求复刻项目交互后，团队需明确实际接口提供方和读写边界，不能把原型的本地存储作为生产事实源。

正式读取、搜索、列表总数、详情和源文件均应按实际权限返回；文件加项目标签、群聊改归属或 Bot 能收消息，不应自动授予源内容的访问权限。项目与来源权限按现有系统契约复用。

配置变更、群聊归属、主群替换、文件项目关联、任务编辑和发送操作应有正式回执与审计。正式发送需处理重复提交、失败和回执未知，保持任务及消息标识可追踪。

### 建议数据和接口任务

接口路径由开发团队按现有规范确定，以下仅列出需要的能力。

- 读取组织树和人员，按稳定 ID 返回选择结果。
- 读取和保存 Bot 配置，分别执行可用性检查和项目权限联调。
- 按账号与来源权限读取会话、分页消息和指定消息上下文。
- 设置群所属项目和项目主群，处理唯一性与改绑。
- 发消息、上传附件、查询发送状态。
- 读取项目八栏对应数据和当前用户可执行动作。
- 查询和编辑任务，提交评论，分页查询字段变更与评论动态。
- 归集文件和云文档内容，按多项目归属筛选，维护关联关系。
- 读取文件来源消息，取得文件预览内容或预览任务状态。

### 需要团队定稿的口径

1. 项目、成员、任务以 OmniGrid 正式接口为事实源的实施边界，以及已有接口可复用程度。
2. 真实消息以 Bot 身份还是已授权用户身份发送，以及两者的权限和显示方式。
3. 任务临期阈值、业务时区，以及优先级枚举映射。
4. 文件同步的群聊范围、历史起点、内容更新和源权限变化的处理。
5. 云文档、纪要和多维表格大小的定义。
6. Office、PDF、ZIP 及多维表格预览的格式、内容范围和保真要求。

这些待定项可在设计对应接口时逐项确认，不应反向阻塞已有明确页面与交互需求的拆解。

## 13 联合验收场景

1. 展开组织树任一分支，核对箭头、叶节点与选中路径；执行展开全部和收起全部。
2. 进入系统管理，分别保存 Bot 配置、验证 Bot 自身状态，再按账号和项目执行权限联调，核对失败原因。
3. 从飞书机器人记录切换群聊与员工 1:1，搜索消息，点击头像或姓名查看浮动基本信息。
4. 拖动会话列表与消息区之间的分隔线，刷新核对宽度；手机打开会话后可返回列表。
5. 把北辰协作群设为主群，核对群名星标；改归属到另一项目，核对两处项目群列表和原主群状态。
6. 在群聊输入多行文字、表情、@ 和附件，核对中文输入法 Enter、空消息、发送失败及正确收件目标。
7. 从项目列表进入八栏工作台，从节点或消息进入对应任务，旧简报链接落到“日报 → 项目简报”。
8. 对不同优先级卡片核对背景和边框；临期任务日期红色带感叹号，已完成任务无临期提示。
9. 按里程碑及负责人联合筛选，切换看板与列表，修改任务里程碑后核对结果集合。
10. 编辑任务标题、正文、负责人、日期、优先级、标签、验收条件和参与人，保存后核对卡片、列表及刷新读取。
11. 清空标题、将截止日期设早于开始日期、受阻不填原因或取消不填变更原因，核对校验与草稿保留。
12. 编辑中关闭或切页，分别执行继续编辑、不保存、保存并关闭；提交评论并切换动态筛选，核对字段前后值。
13. 在文件网盘切换四类文件，核对来源、所属项目、大小和各格式图标，打开预览。
14. 给同一文件关联两个项目，分别按两个项目筛选，再移除其中一个，核对另一关联仍有效。
15. 从文件列表和预览点击来源，在桌面和手机都定位到同群的同一条分享消息，并高亮。
16. 对失权消息、删除的源文件、预览失败、网络错误和重复发送执行真实接口验收，核对返回状态与可恢复操作。
