# 共享 Bot 连接演练窗口

窗口负责人先填真实值班人、UTC 起止、测试账号／群代号、准许的操作与次数、最大可接受的收信中断和恢复决定人。记录切换前的应用身份、有效凭据代次、两个副本的 Ready 和实际镜像、Lease 持有者及续租时间、数据库连接代次、最后一次心跳和最后普通收信。凭据与平台消息正文留在受控系统内。

本次 #20261120-644662a 使用目标集群独立 Deployment、合成账号及本地配置。SDK 与真实 Bot 的下列六项全部**待窗口实测**。已有单连接转交、候选入库、平台夹具及离线断线测试分别保留原证据范围。下表列出窗口责任岗位；开窗时由接班人签名。

| 待验项及影响 | 窗口负责人 | 动作与通过时应观察到的结果 | 停止与恢复条件 |
| --- | --- | --- | --- |
| SDK 握手，可能短时中断普通收信 | 飞书应用管理员、收信服务值班人 | 在已批准应用和唯一连接窗口启用当前有效版本，核对 SDK 实际握手、平台连接状态与 Pong。指定测试者发一条带代号的消息，核对回执、唯一入站和正常消费。 | 握手失败、无心跳或无入站即停止下一项。核对应用订阅及当前有效密钥，恢复已知可用的单一持有者，收到首条普通测试消息后复核。 |
| Lease 换代，切换期间可能积压 | 集群值班人、收信服务值班人 | 两个就绪副本使用同一应用与代次。正常终止持有者，记录旧进程退出、新持有者取得 Lease、数据库连接代次、首个心跳与首条入站的 UTC。核对全程只有一个有效写入者。 | 重叠写入、无人续租或中断超出窗口阈值时停止。收回试验副本，恢复单一有效持有者，核对续租与积压追平。 |
| 旧代次拒绝，迟到回调可能重复写入 | 收信服务值班人、数据库值班人 | 在授权测试连接上暂缓旧持有者的一次测试回调；完成接管后释放该回调。记录旧代次写入被拒，按事件代号核对新增入站与工作均为零，再用新代次提交对照事件。 | 若旧代次提交成功，立即停止测试投递、隔离旧副本，保存代次和账本，完成重复工作对账后再开放。 |
| 断线恢复，期间可能重投或漏收 | 网络值班人、收信服务值班人 | 有界中断测试持有者的 SDK 链路，保留数据库和集群 API。恢复链路，核对断线检测、重新握手、Pong、恢复后首条普通收信；按事件 ID 对账窗口内重投与逻辑工作数。 | 超时或对账不一致，先解除网络故障，恢复已知连接与消费。对结果未知的投递查账后再决定补偿。 |
| 全局 Bot 开关，影响共用应用的所有会话 | Bot 配置管理员、业务值班人 | 记录原开关、待处理工作和配置版本，在获批窗口停用，观察 SDK 退出、代次失效和收信暂停。按原值恢复，核对握手、心跳、普通入站与待处理工作。 | 开关状态与实际连接不一致时停止，按当前配置版本恢复原值，复核唯一连接、收信及队列。 |
| 全局换钥，同时影响登录、目录和收信 | 飞书应用管理员、凭据维护人、发布负责人 | 保存应用标识、当前配置版本和恢复能力，按平台窗口轮换密钥并递增凭据代次，使全部副本使用当前有效密钥。检查旧代次退出，验证正式 OAuth 登录、目录读取、SDK 握手及测试收信。 | 新钥不可用时暂停放量，由应用管理员确认平台有效密钥并重新分发，保留单调递增的代次。必要时用兼容二进制配合当前有效密钥恢复，复核登录、目录、心跳和普通收信。 |

每次只施加一项变更。执行人在下一项开始前记录 UTC、持有者／代次变化、测试事件代号、预期与实际、恢复完成时间和证据位置。窗口结束时，业务值班人签认普通收信恢复，发布负责人登记未通过项、影响范围及放行决定。Lease 参数和状态观测入口见 [飞书 Bot Lease 与长连接复验](../README.md#飞书-bot-lease)。
