# OmniRelay 正式发布记录模板

每个生产窗口复制一份到发布工程的本地忽略目录。由发布负责人填写实值，时间统一用 UTC。每个实测项填写执行人、时间、结果和证据位置。待验项保留原状态，最终签字时可据此判断能否放行。

## 放行核对

1. **确认所提升的制品。** 核对候选实测 SHA、摘要和生产目标平台。按原摘要提升制品。节点交付需核对实际节点镜像内容 ID；转入仓库时保存仓库摘要、平台清单及对应配置摘要的映射。记录生产将使用的引用及其可拉取性。重建的镜像须重新验收。
2. **确认可以退回。** 读取生产当前真实摘要，确认可取回，检查所有入口均能读到新旧静态归档。核对备份时间、恢复验证与步骤，以及上一二进制在迁移后的结构、当前配置和凭据代次上实际通过的业务读写。新旧应用不兼容时暂停放行，由数据库负责人确定向前修复或单独的数据恢复方案。
3. **切换与记录。** 在核对过的生产目标执行发布流程，登记迁移 Job 结果、账本、Deployment 上的上一摘要注解、修订号、实际 Pod 镜像和就绪副本。分别记下 Service 与外部 HTTPS 的 `/readyz` 结果。观察期间暂停下一次版本切换。
4. **生产冒烟与签字。** 指定账号经正式入口登录，核对身份与工作台落点。用已批准会话验证普通收信，记录平台测试事件代号、入站时间、唯一业务记录和积压情况。复核已打开页面的延迟加载及核心业务读写。共享连接受本次变更影响时，附相应窗口实测记录。记录最终决定、人员及 UTC。
5. **触发回退时。** 停止放量，核对上一摘要注解与本记录，确认当前数据仍满足兼容条件。使用目标环境适用的镜像回退脚本，记录实际回到的摘要、Ready、登录、收信、业务读写和归档加载。保持当前有效凭据代次。涉及数据恢复时另记恢复授权、写入冻结范围、备份点、增量对账及复核结果。
