## 实施记录

- 在 `web/index.html`、`web/app.js` 和 `web/login.js` 接入侧栏、移动导航、直达权限及登录返回。Bot 入口依据 `access.admin.feishu_bot`，保存和目录同步入口沿用 Go 当前的管理员权限。OAuth 失败回跳暂存经过白名单校验的站内路由，会话与 CSRF 沿用现有管理请求。
- `web/system-api.js` 和 `web/login.js` 沿用同源请求封装，增加可选条件头、幂等键及 ETag 返回。 `web/feishu-bot.js` 维护保存版本和开关草稿。412 或 428 先重新读取服务端状态，保留草稿并等待再次保存。Go 管理写接口将权限和 CSRF 失败统一返回为 403，页面提示重新登录并复查读取权限，读取被拒时清除已显示数据并停止轮询。
- 检测独立提交，丢失响应后重试复用同一键。仅在 `queued/running` 轮询，终态刷新配置状态。路由退出取消页面请求并清理定时器。凭据校验、Bot 信息读取、长连接和最近真实收信独立引用各自的数据字段。

## 定向验证

- `node --test tests/contract/feishu_bot_client.test.mjs`，两项通过。覆盖 ETag、条件头、幂等键、会话 CSRF、取消信号、旧返回格式、412 错误和同源路径限制。
- `go test ./cmd/omnirelay -run '^(TestFeishuBotManagement|TestBackendFeishuAdmissionAndRevocation)$' -count=1 -v`，使用独立 PostgreSQL 16 和隔离 schema，两项通过且均实际执行数据库用例。覆盖管理员、运维和普通成员、请求来源与 CSRF、412、428、幂等合并和 OAuth 返回路由。
- Chromium 在 `#/system/feishu-bot` 使用 1440×960 和 390×844 分别检查浅色与深色。管理员用 Tab、空格和 Enter 操作开关与保存，用 Escape 返回继续编辑，用移动选择器确认放弃或保存后离开。验证已保存状态与草稿同时显示、412 保留草稿并等待再次保存、POST 响应丢失后使用同键重试、检测终态停止轮询、切页后的晚到结果被忽略。运维可看可测，普通成员无权直达。
- 浏览器通过本地测试桥连真实 Go 与隔离 PostgreSQL。一次性去掉条件头得到真实 428，去掉 CSRF 头得到真实 403，写入 403 后读取仍可用且草稿保留。使用仓库契约样例验证未配置、空时间、平台暂不可用、检测失败及读权限撤销。Chromium 原生回环 HTTPS 导航在当前环境停滞，Cookie 与 Origin 校验由真实 Go 用例复核。Go 的上游飞书响应使用测试传输，真实飞书长连接及群聊或私聊收信由预发布联调覆盖。
- [浏览器截图](../../../../design/engineering/evidence/20261117-977062a)包含桌面浅色、桌面深色、窄屏浅色、窄屏深色与未保存对话框。对照工作台原型的标准表单、信息展示和现有对话框。Bot 配置页尚无独立确认稿，组件复用可核对，整页 1:1 验收以独立确认稿为准。

## 复现步骤

1. 管理员在两个标签页打开 Bot 配置页，先在第一处改变并保存开关，再在第二处修改并保存。观察第二处 PATCH 返回 412，随后 GET 读取新 ETag，草稿仍在。再次点击「保存」，确认使用新 ETag。
2. 在浏览器开发者工具中模拟丢失首次检测的 POST 响应后点「重试检测」。确认两次 POST 的 `Idempotency-Key` 相同。任务终态后等待一个轮询周期，确认检测详情请求停止。再次检测后立即离开，确认晚到响应没有改写目标页面。
3. 在 390px 宽视口选择 Bot 配置，勾选启用但暂缓保存。在移动选择器切换页面，观察未保存对话框初始焦点。分别操作继续编辑、不保存、保存并关闭，核对导航与草稿状态。
