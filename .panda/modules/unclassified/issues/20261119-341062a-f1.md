- P01 明确 OmniGrid 与 OmniRelay 的数据归属、可信身份映射、项目权限和八栏接口责任。规划沿用 `ProjectAccessResolver` 的正式成员门槛，按当前读取者复核项目动作和逐项来源权限，过滤后统一计算条目与总数。正式委派尚未接通时拒绝受保护读取，避免借用服务账号扩大权限。

## 实施结果

- `internal/project` 复用 OmniGrid 个人 API 令牌和 `/api/v1/auth/me` 核对服务端账号映射，经 `ProjectAccessResolver` 验证正式成员与项目动作。项目目录过滤后分页计数，六个 OmniGrid 栏目在回传前复核成员与来源版本。权限委派使用上游的不透明访问版本，版本变化（包括业务日切换）时从严失效。
- `migrations/0012_project_relay.sql` 保存项目群关联、Bot 目标、计划和按业务日生成的简报。简报生成和 E1 投递分别记录。明确允许公开的提交数才能发往当前目标群，E1 发出前复核权限、当前计划与来源。未知回执沿原操作对账，成功确认保留时间。计划表示配置，当前交付由显式发布入口调用 E1。
- `internal/project` 的项目校验独立返回 Bot、群、账号、项目动作与公开范围。校验使用读取操作，隔离数据库验证审计、计划、群关系、简报与投递表均未新增记录。启动和配置契约见 `cmd/omnirelay`、`config/backend.env.example` 和 `design/engineering/feishu-integration-contract.md`。
- 定向验证通过。覆盖授权项目及群来源过滤、分页总数、来源撤权、项目失权、身份错配、只读校验、换群后拒绝旧简报、未知回执按原操作对账、E1 现有回归和 PostgreSQL 迁移。使用隔离 PostgreSQL 与受控 OmniGrid、飞书替身，真实环境联通及联合验收未执行。索引和当前模块未定义 `MODULE.md`，本次沿用现有过程页。
