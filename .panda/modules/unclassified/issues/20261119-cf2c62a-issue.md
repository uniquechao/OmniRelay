## 实施核对

当前集成分支已由 H1 接入本地正式会籍。授权写事务复核操作者的项目管理权、目标账号与会籍代次。保留原有系统授权分页契约，为用户详情单独投影可委派的项目与该代次的授权。模块索引仅有标题，当前过程页归属 unclassified，无对应 MODULE.md。

## 实现与定向验收

- React 角色页沿用用户页的挂载与离开保护。角色数由服务端聚合，项目授权只统计操作者有权委派、目标仍为有效成员且代次一致的记录。候选接口从同一租户和应用筛选操作者管理的项目与目标成员的交集。本地目录使用项目编号作名称。涉及 frontend/src/features/users、frontend/src/features/workbench、internal/access、web/system-api.js 和 web/admin.js。
- 项目选择器提交所选会籍代次。组织写事务复核项目委派权及目标会籍，旧草稿遇到撤销、重新加入后返回 409。用户详情区分无操作权限、无候选、读取失败；提交后的重试只执行读取。
- 项目写入成功只读取目标账号的项目授权投影；系统写入成功只读取该账号及其系统授权。匹配筛选时原位更新角色单元格，移出筛选时从当前范围以 limit=1 补位并更新总数。共用列表组件增加局部页数据更新入口。
- TestAccountGrantsBrowser 在 React 构建、真实 Go 服务及隔离 PostgreSQL 16 上通过。断言了真实选择器到写接口、代次冲突、授权后读取失败、只读重试、关闭重开、重复授权、撤销、候选查询失败、无候选、无操作权限、开通和启停。记录完整系统请求序列，确认部门树、无关授权及非目标账号均未重读；筛选计数从 1 变为 0 时只补读一条。角色计数也经真实接口核对。
- 对照 design/prototype/omni-relay-workbench.html 的用户详情，1366×900 桌面抽屉宽 480px，390×844 窄屏使用全宽。浏览器断言覆盖方向键选择、脏草稿关闭确认、继续编辑、保存反馈和关闭后恢复原行焦点。
- TestSystemRolesBrowser、internal/access 七组数据库定向测试及目录客户端五项契约通过。覆盖默认角色、系统与项目隔离、自身限制、最后管理员、会籍失效及并发修改。本次仅使用隔离数据，未操作生产账号。
