## 实施记录

- `web/system-api.js` 从根部门取得 `snapshot_version`，子部门及人员分页共用该版本，组织树和人员齐备后一起更新。用户管理沿用现有姓名/账号状态查询、按部门筛选、排序和分页，对同一份已加载目录执行操作。409 时清除旧目录和人员抽屉，自动重试；新快照仍有原选部门则恢复，否则向用户呈现根节点。目录档案与已开通的本地账号分开，撤权期间账号接口独立返回的记录仍可管理。
- `web/admin.js` 复用同步详情抽屉，分别显示排队、运行、首次无快照、失败时仍可见旧快照和授权变化隐藏目录。展示最近成功、下次同步、授权范围、人数、部门数和人员差异计数。合并提交展示并入提示。失败原因使用工作台文案映射。读取许可由目录服务响应决定；同步入口依据会话权限，写请求 403 不关闭已有目录。
- 页面生命周期信号取消查询；版本冲突或已确认撤权时废弃旧请求，关闭旧人员抽屉。页面内定期核对后台同步和授权状态，运行期间提高频率。离页、会话失效和读取被拒时清理轮询。
- 明确开通仍调用 `POST /api/v1/system/accounts`。人员按稳定标识展示，多部门路径聚合；列表和详情分别显示账号状态和目录状态。
- 经确认以 issue 6 的正式接口为准，将 `tests/fixtures/feishu/directory.json`、契约文档和离线验证的 `path` 对齐为名称数组。本 issue 处于 `unclassified`，仓库索引无对应模块文档。

## 复现步骤

1. 用隔离 Go 服务发布含不同部门同名人员的测试目录。选中一个部门，输入姓名并设定账号状态。发起同步后，让人员分页携带已失效的快照版本一次，确认接口返回 `409 directory_snapshot_changed`，浏览器重新读取根部门及受影响页面，保留查询和仍有效的部门选择。
2. 让飞书上游同范围返回不完整分页。确认同步详情显示失败原因，列表仍可浏览上一份已授权目录。恢复飞书响应再点「同步」，核对最近成功、下次同步、授权范围和人员变更数。
3. 保持人员详情打开并延迟一次旧版本人员 GET。让下一轮同步确认授权撤回，观察旧部门、旧目录档案和人员详情及时清除。释放迟到响应，核对旧数据未重现。恢复权限后发布去除原选部门的新快照，确认选择回到根而姓名筛选保留。
4. 经 Tab 将焦点移至「同步详情」，Enter 打开，Escape 关闭，确认焦点回到入口。在窄屏切换浅深色并重复。切换到角色权限页，核对同步状态请求停止；重新进入后撤销会话，核对下一次读取返回 401、回到登录页并停止后续轮询。
