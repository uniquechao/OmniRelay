## B1 实施与交接

- `GET /api/v1/me` 的 `access.admin.settings` 沿用 `system.read`，系统管理员和系统运维者可见。`GET /api/v1/system/connections` 独立复核同一权限，使用 `ValidateSession`，读取不延长会话空闲期。
- 连接列表成功返回 `200`，响应为 `{"items":[{"id":"omnigrid","state":"not_configured"},{"id":"deepseek_harness","state":"not_configured"}]}`。ID 对应原型的 OmniGrid Business API 和 DeepSeek Harness，当前均未接入。读取或鉴权服务异常返回 `503` 和 `service_unavailable`，未登录返回 `401`，无权限返回 `403`。连接清单只提供已知 ID 和状态，无主动探测或写入；客户端遇到未识别的 ID 或状态应按未知处理。
- OAuth 允许精确的 `/#/system/settings`，将 `/#/settings` 归一为该路径，将原型的 `/#/system/bot` 归一为 `/#/system/feishu-bot`。回跳仍按各自导航能力授权，无权时使用可访问的默认路径。B2 可按同一映射处理浏览器内深链。
- Bot 检测结果只投影 `tenant_token` 和 `bot_info`。事件订阅和消息权限未纳入主动检测，长连接状态来自既有运行状态。交接决策表 P07 对应简报计划，主动检测范围采用飞书集成契约及现有正式实现。项目权限聚合归 F1。
- 修改集中在 `internal/access`、`internal/identity`、`internal/system`，沿用 Bot 原有脱敏状态、版本／ETag、检测幂等和配置审计。
