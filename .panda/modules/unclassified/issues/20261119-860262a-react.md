## 实施决策

审计路由挂载 React 页面，复用 DataList 与 Drawer。DataList 的远程模式沿用标准列表的列宽、键盘、分页和读失败反馈。审计查询键包含筛选、排序、页大小和游标；游标链归页面实例，会话修订会卸载页面并更换查询客户端。本 issue 的 module_uid 为空，索引无对应 MODULE.md。

## 实现与定向验证

- `frontend/src/features/audit/AuditPage.tsx` 接管审计路由的查询、游标链和详情。`frontend/src/ui/components/Widgets.tsx` 为 DataList 增加远程分页，详情操作从当前已绘制页取记录。`web/system-api.js` 和 `web/audit-display.js` 供两个入口共用分页适配器、显示名称和时间格式。
- `TestReactAuditBrowser` 复用真实 TLS Go 服务与按测试隔离的 PostgreSQL 架构，通过生产路径 `/` 和 `/assets/` 加载 Vite 构建。Chrome 从匿名直达地址登录，在 10,001 条记录下首页显示 10 条。首屏审计列表请求 1 次，响应正文 4,038 字节；匿名探测与登录后核验合计 2 次 `/api/v1/me` 请求。改为每页 50 条后逐页经过 201 页，末页仅有「样例-1」，下一页禁用。
- `tests/integration/react_audit_browser.test.mjs` 验证筛选和排序回到无游标首页、键盘调列宽及播报、翻页保留列宽、抽屉关闭后焦点还原。延迟真实 Go 响应后交错搜索、翻页和离页；另注入单次 503 后手动重试并读取成功。
- 同一标签中，管理员搜索并筛选后打开详情，切换到审计查看者时清空关键词与筛选、关闭原详情，重新显示 10,002 条记录的首页和新登录事件。再切换到普通账号，工作台回到授权入口，直接读取审计接口返回 403。
- Chrome 核对了原型与构建页在 1366px 和 390px 下的可见列。桌面保留时间、事件、操作者、对象、结果、详情；窄屏收起操作者和对象列，事件副行保留操作者。实测浅色桌面、深色窄屏、排序、分页与详情。类型检查、Vite 构建、审计适配器契约和上述 Go 浏览器用例均通过。
