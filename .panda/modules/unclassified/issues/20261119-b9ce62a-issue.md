## 联调结论

- Codex 沿用系统准备的分支与已合入的两个依赖。模块索引无登记项，过程页的 `module_uid` 为空。
- `cmd/omnirelay/system_roles_browser_test.go` 通过服务装配层把权威项目权限测试适配器接入实际 Go 路由和工作台。五个独立账号经真实密码登录，再用 Chromium 和直接 API 请求验证系统矩阵、旧字段、原账号和授权接口。系统和项目授权分别验证，项目权限源报错时写入失败。
- 隔离 PostgreSQL 16.15 上通过历史和新开通账号、停用恢复、角色授撤、权限版本、会话、最后管理员及并发授权与停用、并发管理员停用。派单能力、成员关系及委派代次由项目权限测试适配器覆盖。浏览器核对默认角色人数 5→4→5、系统和项目范围过滤及实际授权列表。数据库中的自动角色授权记录为零。
- `web/app.js` 修复跨标签页切换共享会话后残留旧账号个人信息弹窗的问题。会话刷新切换账号或能力时先清理弹窗和浮层。新增回归在修复前复现并在修复后通过，覆盖桌面和移动导航、回跳、前进后退、授予后旧页刷新、撤权后两页会话失效和重新登录。
- 真实 Go/Chromium 联调、访问控制与身份会话回归、7 项客户端契约测试通过。飞书出站使用替身，项目接口使用权威测试适配器。无头环境用页面焦点事件触发真实会话请求。凭据和部署参数使用专用隔离测试环境，交付文件仅含虚构样例。
- 产品规则、协议样例和复现命令同步至 `design/specs/omni-relay-feishu-integration.md`、`design/engineering/feishu-integration-contract.md` 和 `design/engineering/feishu-integration-acceptance.md`。
