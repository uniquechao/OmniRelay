## P04 澄清与实施规划

- 用户已确认，系统管理员可读当前部署范围内的全部可用 Bot 会话。其他启用账号只能读取自己当前仍是飞书成员的群聊，以及本人和 Bot 的 1:1。C1 提供聊天只读能力。群历史回补从飞书能提供的最早记录开始翻页至末页，包含非 @ 消息和可读取的话题回复；实时归档与业务命令入站分离。
- 历史接口使用应用身份；Bot 所在群及 `im:message.group_msg` 是平台侧前提。平台对历史设置、话题和权限造成的缺口应体现在覆盖范围和同步状态。系统管理员权限只影响本地读取判断，采集仍受飞书授权约束。群成员变更和 Bot 失权应使旧搜索、总数及深链同步失效，撤回消息的正文不得被旧页或重投恢复。 [飞书历史接口](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/list) · [飞书消息与事件概述](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1)
- 历史任务 B1 确认 OmniGrid Business API 未配置，F1 负责正式业务与项目权限接线，E1 负责飞书投递回执与对账。相邻 OmniGrid 的业务插件有任务读取与创建，但已提交文档描述其入口由专用本地进程使用个人项目管理员身份，不能直接作为 C1 的多用户授权回执接口。当前方案按正式提供方的业务回执 ID、正式对象及飞书消息 ID 做可信关联，跟随聊天和目标对象的权限投影；无已核验来源时保留未关联。任务和简报业务操作由原有分工承担。
- 规划分为授权聊天的同步和读接口、依赖正式业务/投递来源的回执接线。两者各自有可独立验收的结果；前端分隔栏沿用 C2 的原始分工。规划阶段只读核对，未改动代码或执行测试。

## 实施结果 · 子任务 1/2

- `migrations/0010_feishu_chat.sql` 增加会话、消息归档和同步游标。现有已验证的入站记录为升级后的会话发现提供标识。群列表由飞书读取，员工 1:1 通过已验证的私聊入站记录及进入会话事件发现。飞书机器人群列表本身不枚举 1:1。对每个已发现会话，历史从飞书返回的最早页开始，话题单独翻页。页内容、续跑游标和状态同事务持久化。
- `internal/feishu` 复用现有 SDK 与应用凭据处理归档事件及历史读取，`internal/store/postgres/feishu_inbox.go` 复用连接代次保护。群非 @、撤回和历史回补均走独立归档。消息按租户、应用和飞书消息 ID 合并，撤回标记优先于旧历史页及实时重投。
- `internal/chat` 由 `cmd/omnirelay/server.go` 注册 `/api/v1/feishu/chats`。支持群聊和 1:1 筛选、成员、历史游标分页、全局和会话内搜索、目标消息上下文及同步详情。刷新使用带 CSRF 的 `POST .../sync`，仅调度读取同步。全部读取校验飞书来源与账号当前权限，普通账号按群成员或本人 1:1 授权。同步详情包含授权范围、最早已归档消息、覆盖截止、话题部分覆盖及失败状态。直达失权使用 `chat_access_lost`，已撤回消息使用 `message_deleted`，来源暂不可用使用 `chat_unavailable`。
- 定向测试通过，使用隔离 PostgreSQL 和飞书 HTTP 替身覆盖两类历史、群与话题分页、断页续跑、重复投递、撤回后重投、管理员与普通成员授权、搜索与总数、深链失权及暂失败。既有入站去重、连接代次、SDK 回调、飞书登录与 Bot 管理及迁移定向回归通过。真实飞书租户联验以应用已发布的读权限和事件订阅为前提，本阶段使用替身验证。 [飞书历史接口](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/list)

## 实施结果 · 子任务 2/2

- `internal/chat/receipts.go` 从 E1 对账账本读取已确认的投递证据，并通过 F1 按当前登录人读取已核验且可读的正式任务或简报回执。核对租户、应用、会话、飞书消息 ID、投递 ID 和正式业务操作、回执及对象标识。同一证据重复返回合并；跨会话、投递键冲突和未核验的结果不投影。E1 保持投递关联的事实源，聊天端每次读取复核目标权限。
- `internal/chat/read.go` 在历史、搜索和目标消息上下文响应的消息项中按需返回 `business_receipt`，字段为 `id`、`project_id`、`target_kind`、`target_id`。该字段仅在会话读取授权与正式目标授权均通过时出现。来源未配置、暂不可用、回执未确定、会话或目标失权时不返回关联。
- `cmd/omnirelay/server.go` 提供正式来源的装配入口。当前分支尚无已配置的 F1 业务提供方或 E1 投递账本，因此默认响应按未关联处理。定向 Go 测试通过，使用隔离 PostgreSQL 和受控业务/投递提供方验证精确重复、跨会话错绑、冲突投递、撤权、未配置和上游不可用，并覆盖历史、搜索、上下文及现有登录授权回归。真实业务和投递提供方联通状态仍为未配置。

## 收尾自检

- 静态对照原始验收项，确认群聊与 1:1 的历史、搜索、计数和上下文均使用授权会话集合，撤回不会被旧页或重投复活，群非 @ 归档不会进入命令收件箱。回执投影核对投递和业务证据，并在每次读取时复核目标权限。
- 收尾修复为飞书查询分配独立超时，保留本地写入和失败重试的时间。会话发现的部分响应按失败保存，Bot 配置失权返回授权状态，异常 JSON 和名称中的空字符按已有安全边界处理。
- 两个实施阶段的定向测试已通过。本次收尾只执行静态差异检查，未运行类型检查、单测或构建。真实回执仍依赖 F1 与 E1 正式提供方的装配，在两者就绪前字段保持未关联。
