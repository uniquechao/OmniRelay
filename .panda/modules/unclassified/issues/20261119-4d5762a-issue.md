# #20261119-4d5762a 实现同源请求、会话隔离及可恢复的权限复核

## 原始需求

将 web/login.js 和 web/app.js 中的请求与会话逻辑移入有类型的客户端。会话拥有受保护的查询缓存、草稿和筛选。区分未登录、已登录、暂时无法核验、身份变化和权限撤回，并定义不同的清理时机。页面上层能在网络恢复时验证身份后恢复工作。

<!-- pandados:acceptance -->
- [ ] 保留 Cookie 同源请求、CSRF、HTTPS 密码操作、204、请求取消、ETag/If-Match、Idempotency-Key 和现有错误语义；后端授权继续生效。
- [ ] 401、退出、账号切换、权限撤销时取消旧请求并清除对应受保护状态。覆盖 A 切到 B 后 A 的迟到响应不能写回 B，包括查询及写入完成回调。
- [ ] 模拟身份复核 503：暂时隐藏或锁定受保护交互，在内存保留普通业务草稿；同一账号且授权有效后恢复。换账号或撤权则清理。密码和部署凭据不纳入草稿恢复。
- [ ] 区分用户操作与自动轮询，沿用既有空闲超时语义；窗口重新聚焦、恢复后退缓存和多个并发 403 的复核均有测试。

## 实施记录

- 生产 Go 嵌入入口和 React 预发布入口共同导入 `web/session-client.js`。JSDoc 类型与 TypeScript 严格检查允许两个入口直接使用同一份模块。请求沿用同源 Cookie、CSRF、HTTPS 密码限制、响应格式、版本条件与幂等键。
- 每次挂载绑定当前会话作用域。切换账号、401、退出或授权快照变化会中止请求并作废完成回调，清理项目与网盘状态、聊天草稿和标签页恢复记录。React 查询缓存随作用域替换。授权比较包含服务端账户的 `permission_version`。
- `web/app.js` 在复核暂时失败时用模态层锁定页面，保留原业务表单、筛选和草稿，清空密码并关闭密码对话框。联网、聚焦、页面恢复与手动重试共用身份复核。只有复核通过才解除锁定。聊天编辑器和项目返回位置沿用整页刷新恢复，需通过账号和授权快照校验；部署凭据不进入恢复记录。
- 自动读请求标记为 `poll`。服务端对该类 GET 只校验会话，继续执行路由授权、CSRF 检查及绝对到期检查，主动请求沿用原续期策略。

## 定向验证

- 请求与会话契约用例通过，覆盖条件头、CSRF、同源路径、204、并发 403、503 后恢复、权限版本变化、明确撤权、401、退出，以及账号切换后查询与写入回调无法提交旧结果。
