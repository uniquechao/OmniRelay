## 验收范围与决策

沿用 K1 的八类格式与 K2 的正式宽抽屉。按同仓主工作区交接表第 13、16 项，分别核对受控飞书来源经正式归档、版本化 HTTP 接口取得的结果，以及浏览器里的恢复与权限状态。当前索引只有标题，过程页元数据为 `module_uid: null`，没有归属模块的 MODULE.md。

## 第 13 项：样本与版本

| 格式 | 通过的样本断言 |
| --- | --- |
| 飞书文档、妙记 | 各自跨过 4096 字分页边界，第二页分别读到正文结论、会议决议。 |
| 多维表格 | 第二张表的记录值正确；跨页字段并集包含末行新增字段，第 51 行在第二页。 |
| PDF | 两页扫描图像的颜色与页码对应。对同一文件先后同步加密、损坏和修复三个版本，再按历史版本分别获取加密状态、转换失败和正确的第二页图像。 |
| DOCX、XLSX、PPTX | 文档段落后保留表格及单元格次序；工作表可切换，明细第二页显示第 51–53 行；第二张幻灯片显示结论和表格。按获批的内容阅读口径验收。 |
| ZIP | 目录区分文件夹、可读成员和嵌套归档。TXT、PDF 及三种 Office 子项按条目读取，内嵌工作表和扫描页均可翻页。 |

`internal/drive/preview_acceptance_test.go` 复用 `internal/drive/drive_test.go` 的隔离数据库。样本从受控来源进入正式索引、同步、归档和 HTTP 处理器，逐件比对指定版本的原始字节与预览任务版本。复测正式抽屉的八类样本，确认原型和正式页面在 1366px、390px 的浅色与深色下均采用 720px 或视口宽度，关闭回到列表入口。

## 第 16 项：失败与恢复

- 在 `internal/drive/testdata/preview/` 补入 `encrypted.pdf`、`encrypted.docx`、`encrypted.zip`。真实加密 Office 曾被归入转换失败，现由 `internal/drive/preview/convert.py` 通过 `olefile` 核对加密包及加密信息两条流。AES ZIP 条目在目录标为加密，读取不返回正文。
- `web/drive-preview.js` 在加密、不支持和超限时提示如何更换来源版本，提供返回并刷新列表；可重试的转换失败沿用重试。已打开的可读预览在窗口回焦、页面重新可见及前台每 30 秒通过任务状态复核授权。失权后清空正文、元数据和相关操作，并重新加载列表。
- 实测撤销来源后，旧任务和结果返回 403，版本原件与下载接口返回 404，按文件名搜索为零。恢复来源授权后可重新获取同一版本。已打开的浏览器抽屉在回焦和定时复核两条路径均清空内容；恢复授权并重新打开后可继续阅读。
- 定向验证通过：隔离 PostgreSQL 上的 `TestPreviewSamples`、`TestFileArchiveAccess`；`internal/drive/preview/test_convert.py` 的三个格式用例；`tests/integration/chat_reader_browser.test.mjs` 中的文件来源回焦、预览撤权和格式恢复三个浏览器用例。飞书侧使用受控来源，浏览器使用受控接口与真实转换结果。本次未操作生产租户，最终门禁留给系统。
