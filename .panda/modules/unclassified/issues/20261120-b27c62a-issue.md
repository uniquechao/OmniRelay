## 实现边界核查

- 当前分支已有候选隔离、运行授权和 OAuth／目录受控代办。`deploy/k8s/candidate/cluster.py` 为候选配置独立数据库和网络边界，`deploy/k8s/candidate/manage.py` 的受控服务持锁同步派发，`cmd/omnirelay/candidate_operation.go` 实现 OAuth 与目录操作。
- `internal/feishu/connection.go` 在生产 Lease／SDK 回调中分别受理命令和归档。`internal/store/postgres/feishu_inbox.go` 在生产库保存入站和工作，按消息去重。撤回与私聊进入由 `internal/feishu/inbound.go` 映射为独立归档事件。现有两条提交路径需要共享固定归属；撤回、文件等后续事件需要从原始资源继承归属，再按当前角色和运行状态校验。
- 交系统规划同一 issue 的数据流，确定生产事务内归属与队列的落点，以及候选跨隔离边界的领取、确认、重启恢复和到期冻结协议。出站设计需接通 `internal/chat/delivery.go` 的发送账本和运行预算，明确未知结果对账、独立撤权及接收端回退的边界。
- 本轮完成代码与部署约束核查，尚未实施或执行故障与真人验收。模块索引未登记该 issue 的模块，`unclassified` 下没有 `MODULE.md`。

## 实施规划

- 保留生产 Lease／SDK 为唯一平台入口。生产库在现有连接代次约束下固定首次归属，匹配项在同一事务内保存入站及待投递记录，事务提交后返回 SDK 回调。规则绑定租户、应用、会话类型、会话和测试身份，结合运行时间限制历史消息；关闭开关或切换规则后重投仍使用原归属，已入站和已归档的历史记录保留其生产归属。普通事件沿用既有受理。
- 候选通过既有受控套接字领取和确认，受控服务通过接收端的独立认证接口访问队列。队列绑定匿名 run、候选锁和服务权限，候选本地按平台消息键幂等复用入站、账号解析和归档，提交后确认领取。回执丢失或进程重启可重领，过期、换版或关闭时冻结未完成的候选事件。候选无需生产数据库凭据或飞书应用密钥。只投递本次范围内的消息及其有权访问的撤回、文件等衍生数据。乱序撤回保留墓碑，并阻止已撤回正文进入候选业务工作。
- 出站通过受控操作接入原发送账本，服务端从已受理事件和当前 run 导出目标及主体。在外部发送前复核角色、期限、撤权和余额，复用稳定幂等键。未知结果先从原账本和平台对账；没有足够证据时保持未知。重试和补偿复用同一授权及预算。入站转交与出站授权独立控制。
- 在同一端到端交付中加入定向故障回归、默认关闭的发布接线和脱敏观测。分别记录接收端与候选版本、接收端上一可回退制品，以及 SDK 接收事件到返回回执的观测区间。隔离故障验证先于接收端发布，真人验收待授权后按登记资源进行。代理事件证据只覆盖候选处理；候选 SDK 握手与代次切换另行演练。

## 实施与隔离验证

- `internal/feishu` 和 `internal/store/postgres/feishu_candidate_*.go` 沿既有连接代次接入归属。测试消息原始入站、候选工作状态、归档和队列在生产侧同事务提交。候选通过版本化的领取租约重试并在本地提交后确认。撤回提升版本，把正文替换成墓碑，并撤销已存在的候选工作。按首次归属排除生产文件索引和任务证据。
- `cmd/omnirelay/candidate_receiver.go`、`cmd/omnirelay/candidate_messages.go` 与 `deploy/k8s/candidate/manage.py` 接通私有 HTTPS 认证、受控套接字、候选 Web 证据和代办。回复由已确认来源推导会话、测试身份和稳定发送键。出站逐次消耗预算，检查项目角色与会话权限，未知回执沿原操作对账。文件只经原分享与角色检查提供登记来源。转交与出站可独立关闭。
- `migrations/0026_feishu_candidate_messages.sql` 增加归属、队列和候选确认记录。发布接线以可选 Secret 保持默认关闭，从制品注入接收端源码 SHA，从现有发布流程读取上一镜像摘要。管理端按匿名 run 记录候选 SHA、经接收端核对的 SHA 和回退摘要。SDK 子进程记录业务回调返回时刻和经过时间，可用事件摘要与归属提交记录关联。使用方式见候选验收入口。
- PostgreSQL 16 隔离容器中的定向回归通过。覆盖无活动规则、无关群、越界候选身份、原子写入故障与重试、普通路径在候选占有领取租约时继续处理、停机重领、重复确认、过期冻结、撤回先于原消息、文件归属、项目来源、候选 Web 与工作账本账号一致、群与私聊各一次平台夹具发送、未知回执对账与独立撤权。候选管理脚本四项用例通过。
- 官方 SDK 本地 WebSocket 线协议回执依次为 200、500、500、200，往返约 52 毫秒、0.97 毫秒、2.30 秒和 0.84 毫秒。业务回调返回和线协议收到 ACK 分开观测。代码验收采用隔离数据库和平台夹具，尚未发布接收端、启用现场规则或执行真人飞书验收。

## 收尾静态自检

- 候选本地提交以接收端签发的领取租约为截止，拒绝超过 run 有效期的租约。Bot 凭据换代在激活事务中关闭旧 run 的转交与出站，保留该窗口内迟到事件的归属。旧进程不能用旧代次继续领取、确认或代办发送。
- 在 `tests/contract/feishu_candidate_messages_test.go` 补充领取过期和凭据换代回归断言。本轮只做静态复核，沿用实施阶段已有的隔离验证记录，新增断言交系统门禁执行。
- 现场仍需按 Go 发布流程交付默认关闭的接收端并记录实际 SHA 与回退摘要。在限定资源上启用后，由指定测试者完成群聊与私聊实收、平台对账和撤权后生产路径复证。候选 SDK 握手与换代单独取证。
