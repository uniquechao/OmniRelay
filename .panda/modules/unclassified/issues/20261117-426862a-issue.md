## 实施与验证

- `web/app.js` 在当前标签页保存白名单路由。401 会记录当前目标，取消或失败后可刷新再试，显式退出和会话恢复会清除已保存目标。恢复时采用 `/api/v1/me` 返回的身份、CSRF 和权限，失去 Bot 权限时显示无权状态。后退缓存恢复时清空旧页面和内存会话，重新请求会话。
- `web/login.js` 保留三种固定错误及旧 `error=feishu` 的本地化操作提示，未知错误使用通用提示。会话响应缺少身份或 CSRF 时保留重试入口。浏览器存储只记录路由。
- `tests/integration/feishu_login_browser.test.mjs` 复用 OAuth 契约样例。Chrome 157 与 Playwright Core 1.58.2 覆盖取消、拒绝、暂不可用、旧错误、未知错误、刷新重试、缺失 CSRF、真实后退缓存、撤权、401、退出、密码登录和改密。原型及正式登录页在 1280×800 与 390×844 对照浅色和深色主题，另核对动效播放与减少动态效果。
- `cmd/omnirelay/backend_test.go` 复用 issue 5 的 Go 后端和飞书传输替身。隔离 PostgreSQL 16 上，Chrome 通过真实 HTTP 入口、回调、会话和退出链路完成三种固定失败回跳及成功恢复 Bot 页。退出返回 204，旧会话返回 401。既有 OAuth 准入、撤销与密码生命周期定向测试通过，相关数据库用例实际执行。
- 预发布应用的真实飞书授权属于跨角色验收。当前索引无模块条目，`unclassified` 无 `MODULE.md`，长期行为及复现命令记入现有接入契约。
