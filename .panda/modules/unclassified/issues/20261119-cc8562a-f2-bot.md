## 实施核对与规划边界

- 已从系统准备的分支核对 F1、D1 和 E2 的交付，三份交接材料取自保留工作树。当前模块索引只有标题，过程页归属为 unclassified，当前没有 MODULE.md。
- 项目列表可复用 F1 的授权筛选和分页，八栏可使用同一个项目 ID。正式路由可沿用原型的 reports/brief，兼容旧 brief 入口。日报提交取 submission_state，简报生成取 generated_at，送达取实际投递状态及确认时间。工作台已有请求取消机制和项目聊天组件。
- 联合验收 07 要求从节点、群消息、纪要及文档定位任务。internal/project/views.go 的任务接口仅透传看板，允许的查询不含任务 ID 或分栏游标，上游分栏返回有限的 items。概览节点提供 task_id，E2 的消息回执也已经生成 tasks/{id} 和 reports/brief/{id} 深链，但 internal/project/http.go 只开放最新简报读取。即使项目授权有效，直接刷新链接仍可能遗漏位于后续分页的任务或历史简报。
- 纪要和文档的上游 SourceSummary 提供 ref、shares、coverage 等字段，当前项目读接口没有按来源查询正式关联任务的契约。需要由项目读取层及关联业务栏目确定同一读取者下的按 ID 定位、关联关系及失权语义。客户端依赖首屏、最新记录或标题匹配均不足以验收。此次仅核对依赖，尚未修改业务代码或运行门禁。

## 实施结果

- 在系统分支 panda/module-25-0 接通工作台、桌面侧栏和移动导航的项目入口。web/projects.js 与 web/app.js 使用稳定项目 ID 组织八栏，复用项目原型样式和正式聊天组件。列表筛选与页码写入地址，返回位置按账号和历史条目恢复。离开栏目取消请求；旧 brief、飞书登录回跳及带记录 ID 的链接均进入对应项目。
- internal/project/records.go 使用当前读取者委派读取任务详情，按来源类型和稳定 ID 匹配已确认或合并的任务证据，遍历证据分页并去重。对无关联的资料区分仍可见与失权。历史简报沿原记录重新核对读取者、业务日来源及目标群权限。项目聊天共用 internal/chat 的目录、消息、搜索、成员和上下文查询，在项目内限制群范围并在输出前复核成员、项目读权和群归属版本。
- 日报分别显示成员提交状态、简报生成和投递状态，成功投递且有确认时间才显示已送达。项目 Bot 展示目标群、接入状态、带时区的计划及最近可见回执，具备项目设置权限时可以执行只读接入验证。

## 定向验证

- 隔离 PostgreSQL、受控飞书及 OmniGrid 替身下，6 项 Go 定向用例通过。覆盖按 ID 读取、跨页证据去重、同名标识的来源类型隔离、来源或项目失权、历史简报、群改绑、项目群读权与登录回跳。
- tests/integration/project_workbench_browser.test.mjs 在 Chrome 中通过。1366×900 和 390×844 各验证浅色与深色，核对已确认原型的八栏顺序以及页面宽度。覆盖筛选与页码恢复、返回焦点、节点和来源跳任务、历史简报刷新、日报与回执分态、只读接入验证、失权以及延迟请求的中止信号。
- 浏览器采用受控接口数据，未执行真实租户联合验收或逐像素验收。当前索引无模块条目，unclassified 未定义 MODULE.md，长期契约依据仍为 F1 和 D1。最终门禁由系统执行。
