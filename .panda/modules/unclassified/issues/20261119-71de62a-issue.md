## 实施决策

- 旧接口沿用编号倒序与数字游标。扩展查询按生产页的显示值搜索和排序，沿用事件类型、结果筛选及分页响应字段；先检查审计权限，再按租户和应用查询。
- 生产页复用标准列表的远程分页入口，只保留当前页记录与已访问页的游标。该 issue 未归入具名模块，索引没有对应的 MODULE.md。

## 查询契约与一致性

- `GET /api/v1/system/audit-events` 仅带 `limit`、`cursor` 时保留原响应与数字游标。页大小默认 50，范围 1 至 100。加入 `q`、`kind`、`result`、`sort` 或 `direction` 即使用扩展查询，响应新增权限范围内的精确匹配数 `total`。末页省略 `nextCursor`，空结果返回空数组。
- 搜索对操作者、事件显示名、对象、编号做不区分大小写的字面子串匹配。两个筛选可叠加，排序列为 `id/time/action/actor/target/result`，方向为 `asc/desc`。生产页初始为 `time desc`，并列项以同方向的唯一编号排序；文本使用中文自然数字顺序。前端用 `recordId` 精确读取大整数编号。
- 扩展查询首页取租户和应用范围内已可见的最大编号。续页沿用此上界及上一页末项，每次在同一只读事务中计算总数和该页内容。首页之后分配的编号在重新请求首页时可见。若较小编号在首页前已分配、但事务较晚提交，它可能进入后续页或改变总数；此前已越过的位置需刷新首页重读。返回首页、改变查询或页大小都会重建游标链。
- `internal/access/audit_query.go` 和 `migrations/0019_audit_query.sql` 实现查询、显示字段映射、中文排序和时间索引。`web/admin.js` 与 `web/system-api.js` 消费单页。前端与 Go 接口共用 `tests/fixtures/audit-query.json` 的首页、末页与空结果样例。

- `TestAuditQueryWebSample`、`TestRoleRevocationAndDisableProtectLastAdmin`、迁移顺序与应用检查、`tests/contract/audit_client.test.mjs` 均通过。前后端共用样例覆盖超过 JavaScript 安全整数范围的两个相邻编号。
- Chrome 运行生产审计页和标准列表组件，以受控分页响应验证首页仅发一次请求、下一页与详情、搜索后回首页、排序与事件类型筛选。系统最终门禁留给系统执行。
