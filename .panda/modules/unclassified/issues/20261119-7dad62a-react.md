## 实施记录

沿用 Go 的配置提交、飞书回调和正常模式 404 契约。独立 React 入口复用工作台表单与加载组件，409 与成功回跳共用可刷新、可重试的等待页。生产初始化页面和哈希资源随 Go 二进制嵌入。

## 实现与验证结论

- `frontend/src/routes/setup.tsx` 接管原表单、字段约束、错误提示与焦点。凭据只随 JSON 请求体提交，页面离开时清空；恢复页面时重新从服务端确认模式。等待页最多检查 20 次，超时可用键盘重新检查。
- `web/web.go` 和 `cmd/omnirelay/setup.go` 提供初始化页面及哈希资源。未配置时根路径返回 303，完成回跳返回等待页，正常模式下 `/setup` 返回 404。两种模式均可提供已返回 HTML 引用的资源，避免切换瞬间出现资源加载失败。
- `TestEmbeddedSetupHTTP`、`TestEmbeddedSetupBrowser`、`TestWebSetupRequiresOAuthAndSavesCredentialsOnce` 和 `TestPreviewUI` 均通过。使用临时 PostgreSQL、Go TLS 服务和 Chrome 实测提交、回调、409 及正式登录交接，飞书服务使用受控响应。浏览器覆盖字段校验、错误焦点、重复提交、取消和读取身份失败后的重试、超时、恢复事件、键盘重试、动效与减少动态效果、桌面浅色及窄屏深色。初始化流程无 CSP 违规，浏览器存储、控制台和请求 URL 未检出测试设置码或 App Secret。
- 前端类型检查、Vite 构建和构建目录双入口浏览器回归通过。构建依赖已写入 README 和镜像构建步骤。
