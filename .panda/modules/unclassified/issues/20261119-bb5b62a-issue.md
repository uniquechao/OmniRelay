## 实现记录

- 以已发布计划 `system-role-permissions-20261118` 的共享权限矩阵和接口协议为准。PandaDOS 只读记录确认执行代理为 Codex，问题属于未分类范围。
- `internal/access` 将角色目录、系统操作点和授权规则集中定义。`system_user` 随启用状态自动计算，复用既有账号和权限版本，无需迁移或补写授权记录。停用期间账号接口返回空有效角色数组，真实授权可通过既有接口查看。
- `internal/identity` 扩展 `/api/v1/me`，OAuth 回跳校验当前菜单能力并使用白名单落点。系统运维者叠加正式项目访问时，由支持项目枚举的权威适配器确认工作台入口。当前运行配置尚未接通该项目权限源，逐项目鉴权继续使用既有解析器。
- Bot 检测提交从 HTTP 到 PostgreSQL 事务均使用 `system.operate`。目录同步复用组织事务锁和 `directory.sync`。可读取系统授权的用户缺少撤权能力时返回 403，其他不可访问的授权继续返回 404。

## 定向验证

- 使用临时 PostgreSQL 16 容器和独立测试 schema，通过历史及新开通账号默认角色、账号列表和启停响应、授权撤销及版本递增、最后管理员保护和项目委派代次测试。并发授权与停用的独立回归连续运行 5 次通过，核对了有效状态、授权数、版本和审计数。
- 通过后端真实 HTTP 集成测试，验证四类系统角色、运维者的目录同步和 Bot 检测、受限写操作、OAuth 有权回跳与缺权回退、停用及撤权失效。飞书出站请求使用测试替身。日志和审计未包含测试凭据、会话令牌或 OAuth 回调参数。
- 身份会话、密码登录、目录同步发布和飞书契约样例定向回归通过。项目导航叠加通过权威解析器测试替身验证。实现后的仓库差异通过 `git diff --check`。
