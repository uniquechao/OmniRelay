## 实施决策

- 用户管理在 React 工作台由 `frontend/src/features/users/UsersPage.tsx` 接管入口，和既有入口共用 `web/admin.js`、`web/system-api.js` 的交互及查询。移除整树遍历、整表账号和授权拼装；账号抽屉按账号编号读取账号与授权，角色目录在打开已开通账号详情时读取。同步任务沿用独立查询和轮询。
- `internal/access/user_page.go` 的用户分页在同一只读可重复读事务内复核账号、目录和角色读权，按租户、应用和可信 open_id 合并账号与可见快照人员。目录姓名优先，保留全部可见组织路径、目录外账号、未开通人员和持久离职标记。角色摘要沿用系统范围的未撤销授权，启用账号附带默认角色。部门筛选包含后代，搜索涵盖姓名、编号、路径、来源和角色名称；先筛选排序，再统计总数并分页。姓名、组织排序沿用中文数字排序，编号打破平局。迁移 `0020_user_list_order.sql` 提供 PostgreSQL ICU 排序规则。
- `design/prototype/omni-relay-ui.js` 的共享树在首次展开分支时读取直接子节点，缓存属于当前快照；展开全部才依次加载后续层级。人员列表、树及浮卡在快照切换、409 或确认失权时一起失效，旧请求不能重新填入。监视请求暂时失败保留目录；监视接口报告失权时另行复核目录读取。
- 本单归属 `unclassified`，索引未登记模块，当前目录没有 `MODULE.md`。
