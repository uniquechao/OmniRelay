# #20261119-7f9362a 用户管理与 Bot 自动轮询不得延长会话空闲期限

## 原始需求

web/admin.js 持续轮询目录状态，internal/identity/store.go 目前会对这些请求更新 idle_expires_at。梳理目录、Bot 检测和会话探活等自动请求，用服务端明确的验证策略区分校验会话与更新空闲期限。后台查询仍校验当前账号、租户、权限与绝对期限。核对 web/app.js 的 401 处理、旧页数据清理和重新登录落点。

<!-- pandados:acceptance -->
- [ ] 用短空闲期限和隔离 PostgreSQL 验证停留在用户管理页且后台轮询持续成功时，会话仍按空闲期限失效。Bot 检测自动查询和会话探活同样不会延长空闲期限。
- [ ] 允许续期的主动业务访问按既定规则更新空闲期限，绝对期限不延长。轮询收到 401 后清除旧管理数据并回到登录，重新登录只恢复当前角色有权访问的路由。
- [ ] 四类系统角色的菜单、直达路由、目录状态读写和跨标签页撤权回归通过。

## 实施记录

- 服务端按路由声明会话策略。目录状态和快照、快照重载依赖的账号及角色授权列表、Bot 状态和检测结果、`GET /api/v1/me` 均只校验当前会话。各路由继续执行原有的账号、租户、应用和权限校验。
- 角色目录、审计查询及通过 Origin 和 CSRF 校验的主动写请求保留滑动空闲期限。身份服务同时检查空闲和绝对期限，续期以绝对期限为上限。
- 沿用 `web/app.js` 已有的 401 处理。它中止当前页面请求、关闭浮层、清空页面及会话状态，并在登录后用新会话权限重新校验先前的路由。
- 在 `cmd/omnirelay/session_idle_test.go` 和 `tests/integration/system_roles_browser.test.mjs` 增加隔离 PostgreSQL 与浏览器回归，覆盖各类请求的空闲期限、已失效会话、旧数据清理和重新登录落点。

## 验证结论

- `TestSessionIdlePolicy` 通过。隔离 PostgreSQL 中各自动查询保持两项期限原值，主动 Bot 写请求续期，角色目录主动读取遇到绝对期限时正确封顶，无效 CSRF、空闲失效与绝对失效均按预期处理。
- 12 秒空闲期限的 Chrome 联调通过。用户管理页和 Bot 检测页持续收到成功轮询后分别收到 401，清除旧页面数据和用户详情抽屉并返回登录。以审计账号重新登录后落到审计日志，仅显示审计菜单。焦点触发的会话探活也已覆盖。
- `TestSystemRolesBrowser`、`TestDirectoryDeparturesBrowser`、`TestFeishuBotManagement`、OAuth 和密码会话生命周期、目录同步及权限定向回归通过。浏览器用例将临时目录改为工作区短路径后通过。
