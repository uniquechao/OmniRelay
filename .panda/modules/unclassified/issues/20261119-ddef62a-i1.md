## 实施前核对

已在当前分支核对 `internal/chat/source.go`、`internal/feishu/chat.go`、列表原型及主工作树中的三份交接文档。现有会话授权和消息历史可复用。文件内容还需要独立核验资源读权，并将读权与当前用户可读的分享来源相交。多处分享同一文件时，来源撤权影响对应分享记录，资源撤权影响所有版本及原件。P04 对撤权时效、本地副本处置和补采期限仍列为待确认事项，决定持久化、同步恢复与读取契约，提交系统规划。本轮仅核对依赖，未运行测试。

## 已确认口径与实施结果

- 以用户澄清为准。用户、来源群和文件同属一个项目即可读。应用须仍有权读取分享消息和资源，用户个人的飞书文档权限不参与判定。首次采集与后续补采均跟随 C1 归档。撤权隐藏对应来源，最后一条路径失效时同步隐藏文件、总数、历史正文与原件，本地副本保留。
- `migrations/0016_feishu_files.sql`、`internal/drive` 和 `cmd/omnirelay/server.go` 已接入已有归档、项目成员、群绑定和 Bot 凭据代次。文件按租户、资源类型和稳定标识去重，分享关联保留应用、会话和消息标识。文件项目初始取自分享所在群；后续读取同时复核文件归属与当前群归属。消息编辑触发重建索引，撤回立即停止展示。
- `internal/feishu/files.go` 使用应用身份复核分享，读取 Docx 正文、妙记文字稿、Base 数据表和分页记录、云盘原件和消息附件。原件分块读写，版本按完整内容摘要去重。过期的工作租约可重领，暂时失败、部分覆盖与撤权自动复核；未完整下载的内容不发布成新版本。
- 列表入口为 `GET /api/v1/feishu/files`，支持 `q`、`category`、`project_id`、`format`、`sort`、`order`、`offset`、`limit`。格式字典为 `/formats`。列表先核验来源，再筛选、排序、分页并返回总数。原件大小为字节数，未知返回空值并在升降序均排末位。每项带当前可读的来源、项目、版本与同步状态。`/{fileID}/versions`、`/{fileID}/versions/{versionID}/content` 和 `/{fileID}/object` 与列表共用授权判断。
- 隔离 PostgreSQL 16 与飞书 HTTP 替身的定向验证通过。覆盖重复分享与版本去重、来源和项目撤权、旧版本直达、零字节与未知大小、排序分页、分块下载中断与恢复、Base 跨页与部分响应、资源拒绝及副本保留。迁移重复应用、C1 历史回补与撤回、后端准入与撤权回归通过。本轮未进行真实飞书租户联验。

## 收尾自检

在 `panda/module-25-0` 静态核对了服务装配、迁移、同步事务、飞书适配器与读取接口。列表以可读分享归并文件后计算总数；历史版本和原件查询再次约束当前可读来源。分块写入失败会回滚本次版本，保留已完成版本供恢复。本轮仅做静态检查，未执行类型检查、单测或构建。
