# #20261121-e06262a 聊天消息里面飞书文档

## 原始需求

文档做个单独飞书文档卡片+图标+标题（不同类型的使用飞书原生的图标显示 ），显示标题。
提提前同步好文档内容，不需要点击才提示“授权后可在此查看飞书内容。”

## 澄清与设计

已逐张核对截图。第一张是知识库预览打开后才出现授权提示，第二张是文档与知识库链接在时间线中都显示为网址。验收需要同时检查打开前的真实标题、对应资源类型的飞书图标，以及打开时已经准备好的正文。

需求方确认“按聊天记录的可见范围共享”。用户能看原消息即可查看机器人取得的快照，无需个人文档授权。

## 设计与实施

- 聊天归档、网盘和聊天文档分别运行后台工作循环。聊天文档使用 PostgreSQL 表 `feishu_chat_documents` 作为持久任务队列及快照存储，以租户、应用、原消息、资源类型和资源键区分来源。新消息和历史归档走同一索引，按机器人凭据代次领取和发布。改动消息正文、类型或撤回时，数据库在同一事务中清除旧任务和快照；晚到的读取结果不能恢复旧内容。
- 机器人同步并定期刷新标题、实际类型和正文。知识库先解析真实对象，电子表格同步可见工作表及各页内容。读取失败记录卡片状态并安排重试。预览沿用原消息接口，在复核工作台会话、飞书原消息及资源后读取缓存正文。
- 两个阅读入口共用文档卡片。时间线保留链接周围的文字，每份文档显示独立卡片、本地随包提供的飞书原生类型图标及真实标题。同步中与机器人无法读取的状态直接显示在卡片，已同步的文档点击后进入右侧抽屉。

## 修改文件与测试

- `migrations/0027_chat_document_snapshots.sql`、`internal/chat/document_sync.go`、`internal/chat/read.go`、`internal/chat/message_preview.go` 及服务接线实现队列、投影和预览权限。飞书读取与电子表格分页实现在 `internal/feishu/` 和 `internal/drive/`。前端涉及 `web/chat-reader.js`、`web/chat-reader.css`、`web/chat-preview.js` 和 `web/feishu-icons/`。
- 隔离 PostgreSQL 定向回归通过：两个入口复用快照，点击和翻页不重取飞书正文，失去会话权限后拒绝访问；私聊文档编辑使原快照失效，机器人拒读生成卡片状态，同步中撤回不会回写快照。飞书模拟传输验证应用身份、知识库真实类型、表格分页、妙记和拒读，消息资源识别回归通过。
- Chromium 定向回归通过：机器人记录桌面浅色、项目关联群手机深色均显示独立卡片和已加载的原生图标，待同步卡片自动更新标题，拒读状态直接可见；文档预览无需个人授权，附件分页、图片放大及键盘返回焦点正常。
