# #20261120-e33362a 总览

## 原始需求

设计一下总览页面 体现项目数 消息 文件  人数 啥的

## 澄清与设计

在现有 `#/workbench` 扩充总览。桌面同排展示指标，窄屏换行。项目速览继续呈现项目名称、类型和阶段，统计指标可跳转到对应业务页。

## 设计与实施

项目、文件和启用用户复用现有分页总数。消息以有权查看、已归档且未撤回的记录为口径，复用聊天读取授权，并提供只读计数接口。页面按导航权限加载指标，单项读取失败显示暂不可用，可以刷新重试。桌面并排放置项目速览和系统入口，窄屏依次呈现。

## 修改文件与测试

- `frontend/src/features/workbench/Overview.tsx` 增加统计、跳转、项目速览和刷新状态。
- `internal/chat/http.go`、`internal/chat/read.go` 增加授权范围内的消息计数。`internal/chat/chat_test.go` 验证普通用户与管理员的范围、消息撤回、权限撤销及来源失败。
- `design/prototype/omni-relay-workbench.html`、`design/prototype/omni-relay-overview.css`、`design/specs/omni-relay-ui-standards.md` 同步示例原型、共享样式和总览规范。
- `npm run typecheck` 通过。隔离 PostgreSQL 16 中的 `TestChatReadAuthorizationAndPagination` 通过。浏览器使用模拟业务响应检查桌面、窄屏、浅色、深色、空结果、权限范围、单项失败后刷新和导航。

## 结果与遗留事项

已在系统准备的分支完成。消息和文件统计受飞书来源授权及可用性影响，页面会显示对应指标的读取状态。最终门禁由系统执行。
