# 登录页与品牌动效同步

采用会话「OmniRelay-设计」最后确认的定场切页方案，以 ../deliverables/omni-relay/ 的登录原型为设计来源。身份和会话仍由现有登录服务处理。

- 复用共享循光成环矢量标志，字标与侧栏背景透明。
- React 品牌组件接收三组文案，八秒定时轮换，标题、说明、特性同步向左退出和从右进入。
- 紫青漂移光晕与十道错开流星，窄屏保留七道。隐藏文档时暂停，减少动态模式停止自动轮换并保留手动切换。
- 正式入口保持账号密码、企业 IM 授权、错误、限流、重试和会话返回，沿用共享主题按钮。
- 正式业务使用严格 TypeScript。原型脚本仅用于设计演示。

## 验证结果

- 严格 TypeScript 检查、前端源码边界检查及生产构建通过。旧 Canvas 信息流实现及调用已移除。
- 登录浏览器测试 8 项通过，覆盖八秒切页、手动切换重置计时、隐藏文档暂停、减少动态、登录成功、授权失败重试、会话权限复核和密码清除。另 4 项需专用 Go 联调夹具的测试按条件跳过，不计为通过。
- 1440×900、1100×720、820×720、390×844、320×620 浅/深色与运行中的原型逐项比对品牌区布局、颜色、字号和 Logo 尺寸；检查页面无整体滚动、表单内部可滚动、200% 文字下操作可达。截图保存于本地忽略目录 `.runtime/login-design/`。
- 共享组件测试曾单独通过桌面/手机、浅色/深色四种组合；重复运行及合跑时，分类下拉的键盘选择出现偶发失败（提交值为空）。基线快照单次运行也通过，尚未定位根因，不把共享组件全量回归计为稳定通过。未改动下拉实现或跳过断言；组件测试仅适配新品牌 API 与动效检查。
- Go `TestPreviewUI` 连同生产资源可达性和工作台/初始化入口浏览器验证通过。修复原有构建许可证文件未被入口引用的问题：由构建插件注入 `rel=license`，两入口共享唯一文件名。
- 本地 HTTPS 预览以最新 Go 后端和构建资源启动，实际账号密码登录、会话进入工作台和侧栏透明底 Logo 验证通过。第三方 IM 使用本地身份夹具，未声称完成真实飞书租户联调。
- 按 Impeccable 和实时 Vercel 指南核对。装饰栅格、光晕及流星来自用户已确认设计，保留其视觉；隐藏和减少动态模式停止相关装饰动画。

本次未修改正式认证服务、角色或组织业务规则。拉取前的既有 stash 保持原样。

## 繁星背景补充

按用户后续要求，在品牌区增加 64 颗固定位置、错开周期和延迟的紫青淡白星点，仅改变明暗。与原型同步；沿用隐藏暂停及减少动态模式。类型检查和构建通过，实际 HTTPS 页面确认星点明暗变化、装饰层不拦截操作、390px 无横向溢出，减少动态模式停止闪烁。截图为 `.runtime/login-design/stars-desktop.png` 和 `stars-mobile.png`。

用户指出原型仍新增 JS 后，移除繁星的原型脚本生成逻辑，改为 HTML 静态星点和共享 CSS。正式页面继续使用严格 TypeScript 的 `BrandMotion.tsx`；源码门禁禁止正式前端的 JS/JSX 文件和原型脚本导入。

## 合并验证

用户明确要求合入 OmniRelay 独立仓库的 `main` 并推送。此次由当前 `origin/main` 基线建立 `codex/20261125-login-brand`，仅纳入上述设计、正式 TS/TSX 实现、共享弹窗焦点修复、测试和构建许可证入口改动。

本轮重新运行：类型检查、源码边界检查、生产构建、`go test ./...`、包含浏览器入口检查的 `TestPreviewUI`、登录专项 8 项和共享组件桌面/手机浅深色四组全部通过。4 项专用 Go 登录浏览器夹具用例按环境跳过，未计为通过；依赖单独数据库配置的 Go 测试未声称完成真实租户联调。之前共享组件键盘选择的偶发失败保留历史记录，后续最终复核再次复现，根因和修复见下文。

实际 HTTPS 预览再次验证密码登录、会话进入、透明侧栏字标和繁星；繁星静态原型无需新增 JS 生成逻辑。此次交付为仓库代码合并，不包含生产发布。

合并前独立审查发现 200% 文字在 320×568 与 390×716 会使品牌区占满短屏，现已限制窄屏品牌区最大高度，保证表单至少 `min(320px, 50dvh)` 的内部滚动空间。新增用户名/密码真实点击与焦点、企业 IM 可点击及视口范围断言；独立复核四种窄屏尺寸后关闭该 P2，无其余阻塞发现。

最终复核通过初始化事件日志和调用栈定位共享组件失败：弹窗原生关闭后，异步 `close` 监听器再次无条件恢复旧焦点，发生在下拉的 ArrowDown 和 Enter 之间，导致 `show()` 清空活动选项。共享控件现仅在焦点仍属于关闭流程、且 `onClose` 未主动转移焦点时执行显式恢复；原型同步。新增确定性回归在旧实现上失败，修复后四组尺寸/主题通过，保留普通关闭、草稿确认和真正选择后的提交断言。独立复核无阻塞问题。

修复后的最终组合回归：登录专项和共享组件共 9 项通过、4 项专用联调用例按环境跳过，0 失败；类型检查、生产构建、Go 测试及带浏览器的 `TestPreviewUI` 通过。

## 登录区域比例调整

上一版将左右栏比例写反。按用户确认，桌面左侧品牌区占 70%，右侧登录区占 30%；720px 及以下沿用上下布局。正式登录页和原型共用栅格。浏览器回归按区域名称分别测量宽度，独立检查两种主题和断点两侧。

本次实测 1440px 下品牌区为 1008px、登录区为 432px，1100px 下为 770px 和 330px。登录及共享组件回归通过 9 项，4 项按夹具条件跳过；类型检查、生产构建和 Go 入口回归通过。
