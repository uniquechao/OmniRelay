# #20261120-ab3362a 用户管理可以标记未激活用户为普通用户

## 原始需求

普通用户即可登录系统 未标记的不能登录系统

## 澄清与设计

标记普通用户沿用管理员开通账号流程。开通后账号启用并获得默认角色 `system_user`，登录继续要求飞书校验身份并匹配到已启用的本地账号。

## 设计与实施

在通讯录快照中保留飞书明确未激活的标识，与冻结、退出、未加入、离职和未知状态区分。既有快照的 `inactive` 无法追溯原始原因，需要重新同步后才能识别未激活人员。用户详情复用开通确认和列表刷新流程。

## 修改文件与测试

- `migrations/0022_directory_unactivated.sql`、`internal/directory/feishu.go`、`internal/directory/service.go` 保留明确未激活标识，统计该标识的变化。
- `internal/access/admin.go`、`internal/access/user_page.go` 扩展账号开通资格及列表状态。开通复用当前可见快照、管理员权限、事务和审计。
- `web/admin.js` 在用户详情展示「未激活」，通过「标记为普通用户」确认后刷新列表和详情。
- PostgreSQL 16 定向验证通过，覆盖全新迁移、旧库升级、飞书状态判别、快照发布、开通权限与停用账号保护。模拟飞书 OAuth 验证同一人员开通前被拒、标记后以普通用户身份登录、停用后再次被拒。
- Chrome 定向验证通过，覆盖桌面浅色和窄屏深色的用户详情、键盘操作、取消后的焦点恢复、确认后刷新角色和账号状态。修改文件的界面检测未报告问题。

## 结果与遗留事项

- 原始需求已实现。旧快照升级后通过重新同步通讯录识别明确未激活的人员。生产飞书未接入本地验证。
