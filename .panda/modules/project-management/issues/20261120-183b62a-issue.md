# #20261120-183b62a 项目管理

## 原始需求

实现项目新增 修改项目基本信息 归档功能

## 澄清与设计

沿用本地项目目录、项目成员授权和档案版本。创建由系统管理员操作，创建者成为首位项目负责人。项目负责人和具备有效项目设置授权的成员可编辑档案及归档。

## 设计与实施

项目档案、成员初始化和审计使用同一事务。业务时区复用任务看板，归档保留项目及历史读取，关闭简报发布并记录阶段变化。工作台复用项目列表和项目概览的标准抽屉。

新建默认「规划中」并使用 `Asia/Shanghai`，支持名称、类型、阶段、背景、计划日期和时区。创建重试使用同一幂等键。编辑发生冲突时，重新读取最新档案，保留用户修改的字段并回填同事更新的其余字段。归档需确认，旧项目即使尚无档案也可以按版本 `0` 归档。

## 修改文件与测试

- `internal/access/roles.go`、`internal/project/` 新增创建、归档、版本校验、审计和简报联动，`migrations/0024_project_profile_dates.sql` 新增可空的计划日期。
- `web/projects.js`、`web/project-profile.js`、`web/workbench.css` 接入权限入口、标准抽屉、草稿保护和归档确认。
- 在隔离 PostgreSQL 上验证了创建幂等、系统角色和成员权限、档案和时区冲突、旧项目归档、日报及历史简报仍可读、归档后拒绝简报生成与投递，以及迁移顺序与应用。飞书投递路径使用本地测试桩。
- 浏览器在 `1366px` 和 `390px` 的浅色及深色主题下验证了项目新增、日期校验、权限入口、关闭和切页时保留草稿、冲突处理与归档确认，并核对了标准抽屉宽度。既有项目导航、来源深链、列表返回及权限回归通过。

## 集成核对

目标分支已使用迁移编号 0022 和 0023，项目计划日期迁移顺延至 0024。迁移顺序测试通过，项目工作台脚本及浏览器测试文件的语法检查通过。

## 结果与遗留事项

已完成项目新增、修改基本信息和归档。归档目前为单向操作。最终门禁由系统执行。
