# 项目群 Agent 请求和独立 Runtime 镜像

本次交付以成员在绑定群 @Bot 询问「我是谁」为入口。复用项目档案、群归属和正式成员授权。

| 工作包 | 验收行为 |
| --- | --- |
| Gateway 与持久工作 | 接受同一消息两次只有一个工作，群重绑、成员撤销或重新加入后旧工作失效 |
| Runtime 镜像与只读工具 | DSH 会话仅暴露身份工具。真实工具在 Go 根据当前工作读取四个字段。卷恢复后续用原工作 |
| Channel 与回执 | Go 生成署名，以原消息 ID 在原话题回复。飞书回执不明时保留未知且不自动重发 |
| 内部门槛 | 隔离 PostgreSQL、真实 Runtime 镜像和内部 Channel 完成验证，群消息适配器单独运行契约测试 |

## 实施与取证

- Go 使用通道无关的 `group.Envelope`。正式成员表和群归属代次限定工作权限，迁移 30 分开保存业务工作和通道原始入站回执。飞书适配器在原入站事务内建立关联。
- Runtime 以非 root 身份运行，实例目录和 SQLite 接受日志位于卷上。只读插件使用本轮专属桥调用 Go。Go 在真实 DSH 轮次开始时登记会话和代次，并从真实工具回执生成署名和正文。
- 运行 `tests/integration/group-agent-gate.sh` 同时要求 `TestGatewayPermissionGate` 和 `TestRuntimeImageGate` 实际通过。模型只看到一个无参工具。已验证两个成员、服务身份证书、非法选择器、撤权、重放、容器重启及原话题交付。真实飞书身份和平台调用均不参与此门槛。
- 适配器测试 `TestGroupAgentInboxAdapter` 验证飞书原工作与内部工作对应，`TestGroupAgentReplyContract` 验证原消息寻址及话题回复参数。测试使用受控数据。真实外部收件和生产部署未执行。
- 群身份查询已覆盖同一持久卷恢复。跨节点自动接管和其他业务工具继续单独实施。

## 私聊和主动联系

- 用户私聊「我是谁」时，Gateway 依据入站私聊和已启用账号路由到全局查询助手。原群归属和会籍不会带入私聊，回程保留原私聊的消息 ID。
- 项目管理者可登记及停用单次提醒。迁移 31 记录计划、群与个人各自的授权和投递工作。Runtime 通过双向 TLS 发现归属自己的计划，DSH Harness 负责到点唤醒，Go 校验定时器和授权、按目标取数并投递。群内工具结果仅含项目字段。
- 内部验收脚本同时执行原两项门槛与 `TestPrivateReplyGate`、`TestDirectedNoticeGate`、`TestNoticePermissionGate`。新增门槛覆盖独立私聊、定时群发和个人定向、受众数据隔离、重复登记和回调、撤销计划及成员撤权。适配器用本地服务核验飞书收件类型和回执。验收使用内部 Channel。
- 实测在原生定时器绑定后、到期前重启 Runtime，沿用同一持久卷和定时器 ID，最终得到两个独立会话和两条回执。另在个人提醒完成只读工具调用后撤销收件人会籍，工作进入 `suppressed`，内部 Channel 未收到该条消息。

## 独立部署 DSH 服务

Runtime 使用单副本 StatefulSet、独立持久卷、集群内双向 TLS 服务与文件挂载的模型 Secret。进程存活、模型凭据已挂载、真实模型轮次分别验收。首次配置及轮换凭据均可从终端隐藏输入，显式模型探针使用隔离会话。环境和发布证据保存在部署交接目录。

## 工作台项目 Bot

项目「Bot」是站内通道，POST 只接受消息正文和重试键。服务从登录会话取得身份，按项目和会籍代次分开历史，核验工具回执并将模型原文与项目署名一起提交。Go 私有回调使用独立证书。原飞书接入状态及验证入口仍可由 Bot 页打开。

集群候选工作台使用隔离账号登录。项目成员第一轮核对到本人和项目，第二轮复述第一轮的随机校验词。两条署名回复对应同一 DSH 会话、两个轮次和两次有效工具回执。重复提交复用原工作，同项目另一名成员读取到自己的空历史，非成员被拒绝。这一验收通过站内通道完成。

另用 Chromium 在候选工作台以第二名项目成员登录，从项目 Bot 页面发问，收到带本人姓名和项目署名的真实模型回复，刷新后可恢复该条问答。两个成员在同一项目对应两个不同的 DSH 会话。


## 项目 PM 业务工具

项目 PM 已接入项目档案、成员、群、文件、任务、日报共 20 个工具。Go 从工作与轮次取得账号和项目，核验会籍、动作与对象授权。迁移 34 保存写入回执、来源核验依据和群内请求的个人结果。Runtime 持久化工作内命令序号。

[逐工具功能和权限验收表](../../../../design/engineering/project-pm-tool-capabilities.md) 与 `TestProjectPMToolMatrix` 对应。内部门槛另覆盖跨项目、跨账号、委派失效、写入重试、来源撤权、DSH 镜像、原话题署名和工作台历史，不要求真实飞书账号。生产部署和外部渠道联调独立记录。

内部验收已通过。真实 DSH 镜像调用 Go 工具后，在北辰创建了一条由发起人负责的任务；原话题只收到署名提示，另一成员无法读取其私人回复。20 个工具的同名用例、9 项 Gateway/Runtime 门槛、SQLite 命令日志恢复和带隔离 PostgreSQL 的全仓 Go 回归均通过。逐项结果保存在本地 `.runtime/group-gate.0Q4U4k/pm-tools.log`、`.runtime/group-gate.0Q4U4k/gates.log` 与 `.runtime/pm-tools.buJ7bd/all-final.log`。

### 项目 PM 对话界面（2026-11-22）

根据项目详情 Bot 页截图，将空会话改为三个可编辑的提问入口，分别查询项目进展、任务和成员。选择后在消息框编辑，点击发送才调用原有接口。有历史时按提问和署名回复排版。工作台按可用宽度约束对话行宽，窄屏入口纵排，项目标签栏滚动到选中项。

改动位于 `web/project-bot.js`、`web/project-bot.css` 和 `web/projects.js`。浏览器回归 `tests/integration/project_workbench_browser.test.mjs` 通过工作台正式入口和模拟接口核对选题、编辑、发送、回复与飞书接入，在 1366px 和 390px 下覆盖浅色、深色。界面验证使用测试项目，线上模型与部署独立验证。

### 嵌入 DSH 原生聊天

Bot 标签按需加载与 Runtime 对齐的 DSH 0.2.2-rc.2。官方 ConversationRoot、HeroShell、InputBar、DraftEditorRuntime、UserMessageBubble 和 MarkdownText 负责呈现与编辑。工作台将当前账号的项目历史、提交和重试接到这些组件；发送沿用原站内 POST 和幂等键。飞书接入仍从对话标题栏打开。

标签栏下方按工作区实际宽高布局。空会话显示 DSH 欢迎区；有消息时历史区独立滚动，输入栏停靠底部。类型检查、干净安装与生产构建通过。浏览器使用受控项目接口，覆盖桌面和手机的两种主题、实际边界尺寸、50 条历史、Markdown、键盘换行和发送、同键重试，以及权限失效后的历史清理。截图在工程根目录 `artifacts/dsh-project-chat/`。本次未部署。

### 主群设置回执与历史查询

生产中两次主群写入均已提交，原对话读取的群状态却在回复校验中被判定失效。设置主群后，在同一写入事务更新本次群列表读取中变更的归属元数据，保留该次读取的组与名称。后续调用和展示继续校验来源。历史查询变化返回过期状态。原回复被隐藏时，当前仍具备权限的请求者可看到已提交的主群设置回执。历史读取不重放操作，也不返回原回复数据。
